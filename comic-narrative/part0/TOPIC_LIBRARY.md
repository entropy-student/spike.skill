# Part 0 — 历史选题库

本文件是漫画叙事的历史选题库与扩展候选储备。  
当前保留 **33 个 Case：11 个已接受 PASS 基线；22 个扩展候选仍需完成事实证据 Gate 后才可升级为正式 PASS**。

规则：
- 当前仅保留 Owner 本轮确认的 33 个优先题；已删除的 Case 不再作为当前选题库存；
- Case ID 是稳定标识：删题后不回收、不重排、不复用旧 H-ID，避免破坏既有剧本、素材包、Review、X 库与历史证据引用；
- 当前 11 个 `PASS` Case 继续保留原 accepted 状态；22 个 `CANDIDATE / EVIDENCE_PENDING` Case 不得描述成正式 PASS；
- 新候选在最终 PASS 前必须与本库全部已接受题和候选题做 D1–D5 复查，并完成 Part 1 要求的事实证据 Gate；
- 正式进入制作的选题应继续追加到本文件；
- HOT 题未来应在 Source / Signal 中保存真实来源或事件标识，便于 D1 复查；
- 题面优先使用普通人自然会说的话；
- “科技”包含人工智能，但不强行把推荐算法、平台设计、自动化、设备等都写成人工智能；
- 选题不默认走“反思科技代价”，允许惊奇、机制、实用、判断、趋势、探索、体验等方向。
- `选题类型` 以斜杠前的标签作为**主类型**，用于题库结构与数量统计；斜杠后的标签只表示辅助属性。
- 不因为每个题都存在“主机制”就自动把它归为机制型；机制型只用于“理解机制本身就是主要观看收获”的题。
- 当前 33 题的主类型统计为：判断 10、机制 5、体验 5、惊奇 4、趋势 3、反思 3、实用 2、探索 1；这是当前库存结构，不是未来新增题的硬配额。

## H001 — 美食推荐

- 最终选题：**一年只吃评分最高的餐厅，为什么后来什么都不好吃？**
- 选题类型：惊奇 / 反思
- Entry：HUMAN_WORLD_FIRST
- X：美食
- Human Process：餐厅发现 / 口味形成
- Human Problem：推荐越来越准，但自己的探索与口味形成越来越窄
- 反常：推荐越来越“最优”，主观体验却越来越没惊喜
- Human Tension：最优化 vs 探索
- Controlling Question：当系统越来越会替你选“最可能喜欢的”，你还会不会形成新的喜欢？
- 科技改变的过程：推荐系统的排序压缩主动探索和随机发现
- 主机制：推荐系统持续优先高概率匹配，会降低探索暴露
- Audience Payoff：理解“更准的推荐”不等于“更丰富的体验”
- Meaning Fingerprint：`OPTIMIZATION_VS_EXPLORATION`
- Motif：连续去高分餐厅 → 越来越相似 → 主动走进无人推荐的小店
- Content Job：DISCOVERY
- Source / Signal：EVERGREEN_CASE
- Status：PASS

## H024 — 自助收银

- 最终选题：**超市里的收银台越来越少、自助机越来越多，结账这件事到底是谁在做？**
- 选题类型：趋势 / 判断
- Entry：HUMAN_WORLD_FIRST
- X：零售 / 自助服务
- Human Process：结账 / 获得服务
- Human Problem：自动化看起来减少了收银工作，但扫码、装袋和处理流程的一部分也转移给了顾客，员工则更集中处理异常
- 反常：机器越来越多，本应意味着“人做得更少”，顾客却可能亲手完成了更多结账动作
- Human Tension：服务自动化 vs 工作转移
- Controlling Question：一项服务被“自动化”以后，原来的工作究竟消失了，还是有一部分换了执行者？
- 科技改变的过程：自助终端把标准扫码、确认和支付步骤交给顾客操作，把异常验证集中给少量工作人员处理
- 主机制：自助系统通过标准化流程重新分配人与机器、顾客与员工之间的任务，而不只是简单减少人工
- Audience Payoff：看到“自动化”除了替代工作，也可能把工作重新分配给使用者
- Meaning Fingerprint：`SERVICE_AUTOMATION_VS_LABOR_TRANSFER`
- Motif：传统收银台 → 自助区越来越大 → 顾客自己扫码装袋 → 一个工作人员同时处理多台机器的异常
- Content Job：DISCOVERY
- Source / Signal：EVERGREEN_CASE；EVIDENCE_PENDING（正式 PASS 前必须补足可追溯来源）
- Status：CANDIDATE / EVIDENCE_PENDING
