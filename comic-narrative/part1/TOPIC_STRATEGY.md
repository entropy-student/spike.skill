# Part 1 — 选题策略

## 1. 目标

把“大家本来就关心的东西”变成一个：

> **值得点开、值得追问、能讲成故事、科技真正参与因果、而且没有和历史选题换皮重复的 WHY 选题。这里的“科技”包含人工智能，也包含推荐算法、自动化、平台机制、智能设备、数据系统等。**

本模块只负责选题，不负责完整剧本、分镜、配音或成片。

---

## 2. 默认选题路径

优先从人的世界出发：

```text
X（美食 / MBTI / 娱乐 / 工作 / 关系 / 天气……）
→ Human Process：人在这里原本做什么
→ 反常现象：本来应该 A，为什么却 B？
→ WHY
→ 人类矛盾：两边都合理的力量发生冲突
→ 科技改变了原来哪个人的过程
→ 一个核心科技机制
→ 人的后果
→ 最终 WHY 选题
```

最短口令：

> **X → Human Process → 反常 → WHY → 人类矛盾 → 科技改变什么 → 一个机制 → 选题**

### 强科技热点兼容路径

如果入口本身就是新模型、新 Agent、新功能：

```text
科技变化
→ 这会改变普通人的什么事情
→ Human Process / Human Problem
→ 反常 / WHY
→ 人类矛盾
→ 一个核心机制
→ 最终选题
```

科技热点不能只因为“新”就进入选题。

### 题面先说人话

内部可以用抽象结构思考，但最终选题必须像普通人真的会问的问题：

- 优先写具体场景、具体感受、具体动作；
- 少把“注意力自主、最优化、身份定义”这类抽象概念直接写进标题；
- 如果删掉技术名词后题目更自然，就不要强行把技术写进标题；
- 技术可以在后面的故事和解释里出现，不必抢着做标题主语。

> **先让人认出自己的生活，再解释背后的科技。**

---

## 3. 五个必须通过的检查

候选题必须同时满足：

1. **人会关心且受众适配**：拿掉技术名词后，这个问题仍然值得普通人关心，并且适合当前账号受众。
2. **真的有 WHY**：不是把知识标题后面加问号，而是存在真实预期落差。
3. **科技真在因果链里，而且机制准确**：必须能说清到底是哪一种具体科技改变、压缩、替代或放大了什么过程；如果真正起作用的是推荐算法、平台设计、自动化或设备，就不要硬写成人工智能。核心机制不能为了故事好看而失真。
4. **一条只讲一个主机制**：多个机制才能成立时，拆题。
5. **能讲成故事且有非平凡收获**：能出现行动、阻力、后果、变化；看完不能只剩“科技可以做 X”。

事实型题目必须有可追溯证据。没有证据时，不能把猜测写成事实。

### 不默认做“反思题”

科技选题不只问“科技让我们失去了什么”。候选可以来自多种方向：

- **反思型**：解决一个问题后，又带来了什么代价；
- **惊奇 / 机制型**：一个熟悉现象为什么会这样；
- **实用型**：理解机制后，什么时候该怎么做；
- **判断型**：什么时候该用，什么时候不该用；
- **趋势型**：某种科技变化正在怎样改写原来的习惯或规则；
- **探索 / 体验型**：科技正在怎样改变一种熟悉体验。

同一批候选应主动混合这些方向，不设固定比例，也不默认“反思型”优先。

---

## 4. HOT / EVERGREEN

### HOT
近期事件、新产品、新算法、新人工智能能力、新平台/设备变化或新的社会讨论。

只有同时满足：
- 信息真实且新鲜；
- 能翻译成人的问题；
- 通过五个检查；
- 通过历史选题库复查；
- 来得及在热点失效前制作；

才可以抢占普通选题。

### EVERGREEN
长期存在的人类问题、反直觉现象、用户困惑、稳定机制。

没有合格 HOT 时，从 Evergreen 里选。

> **热点有抢占权，但没有免检权。**

---

## 5. 历史选题库复查

候选题通过前面的内容检查后，**必须读取**：

`../part0/TOPIC_LIBRARY.md`

然后再决定是否 PASS。

复查顺序：

### D1 — 同一信号

HOT 题先看是否只是同一新闻 / 同一事件 / 同一来源的重复包装。

- 同一信号：合并或 HOLD。
- Evergreen 一般跳过 D1。

### D2 — 同一题

比较：

```text
Topic Fingerprint
= 主机制 + Human Process + Human Problem + Audience Payoff
```

如果四项高度一致，即使标题不同，也按重复题处理。

### D3 — 同一角度

技术对象或场景不同，但如果实际还是在讲：
- 同一个人的问题；
- 同一个主要结论；
- 同一种观众收获；

默认 HOLD，不因为换了 X 就当新题。

### D4 — 同一故事 / 视觉母题

比较历史 Case 的 Motif。

如果只是 D4 重复：
- 选题本身可以继续；
- 但必须提醒下游更换故事表达 / 视觉结构。

D4 单独命中，不直接否决选题。

### D5 — 同一意义

比较：

```text
Meaning Fingerprint
≈ Human Tension + Controlling Question
```

如果表面领域不同，但核心仍在问同一个问题，默认 `HOLD_DUPLICATE`。

只有以下内容发生实质变化时，才允许重讲：
- 主机制真的变了；
- 出现新的人的后果；
- 目标受众不同；
- 内容任务不同；
- 旧题留下明确未解决的问题；
- 新热点让旧问题重新重要；
- Human Process / Stakes / Counter-Idea 实质变化。

只是换标题、换领域、换例子，不算新题。

### 最终结果

- 没有实质重复：`PASS`
- 重复但满足重讲条件：`PASS / REVISIT`
- 实质重复：`HOLD_DUPLICATE`
- 本身不满足选题要求：`RETURN`

正式进入制作的 PASS / REVISIT 题，应追加进第零部分历史选题库。

## 6. 传播与长期价值

通过硬检查以后，再比较：

### Reach
- 问题是否一眼能懂；
- 是否有明显好奇缺口；
- 是否反常；
- 是否值得分享；
- 是否有真实需求 / 讨论信号。

### Asset Value
- 是否建立新的理解；
- 是否长期可搜索；
- 是否有系列空间；
- 是否建立信任；
- 是否可能自然连接未来产品 / 工具需求。

同等通过硬检查的候选中，优先选择现实行动与后果更强、能以故事而非解释承载、观众知识增量更高且事实验证边界更清楚的题；反之降低生产优先级，但不因此自动 RETURN。

库级结构复查：若多个候选虽题材不同，但 Human Problem / Human Tension / 主机制 / Audience Payoff 大部分高度相似，视为同一母题簇；同一簇默认只优先保留 1–2 个最强代表，其余降优先级或淘汰，除非人的后果、机制、受众或 Content Job 有实质差异。

不使用一个总分替代判断。

---

## 7. 不要做什么

默认降权或 RETURN：

- “什么是 X”式百科题；
- 技术圈很重要，但普通人没有后果；
- 科技只是标题标签；
- 同一个意义换美食 / 购物 / 音乐外壳；
- 为了热点放弃事实准确性；
- 为了转化硬塞产品；
- 在选题阶段提前决定唯一观点，再找故事证明它。

## 8. 参考 Case

### Case 1 — 美食 + AI 推荐

输入：

> 长期只吃 AI 推荐里评分最高的餐厅。

产出：

- 最终选题：**一年只吃评分最高的餐厅，为什么后来什么都不好吃？**
- Human Process：餐厅发现 / 口味形成
- 反常：推荐越来越“最优”，主观体验却越来越没惊喜
- Human Tension：最优化 vs 探索
- AI Changed Process：推荐排序替人压缩了主动探索和随机发现
- 主机制：基于既有偏好 / 可量化信号的推荐排序，会持续优先高概率匹配而减少探索
- Meaning Fingerprint：`OPTIMIZATION_VS_EXPLORATION`
- 历史复查：命中 Part 0 H001；本 Case 是规则示例，不重复进入制作
- 结果：`REFERENCE_CASE`

### Case 2 — MBTI + AI 分析

输入：

> AI 根据一个人长期聊天记录越来越准确地判断他的 MBTI / 性格。

产出：

- 最终选题：**人工智能测出来的性格越来越准，这个标签到底该信到什么程度？**
- Human Process：自我理解 / 身份判断
- 反常：描述越准确，本应更了解自己，却可能越来越按过去的标签限制未来选择
- Human Tension：被理解 vs 被定义
- AI Changed Process：人工智能把零散的过去行为持续归纳成稳定画像，并让画像反过来参与判断
- 主机制：基于历史行为的模式归纳 / 分类只能描述已有证据，不等于定义未来可能性
- Meaning Fingerprint：`UNDERSTANDING_VS_DEFINITION`
- 历史复查：命中 Part 0 H002；本 Case 是规则示例，不重复进入制作
- 结果：`REFERENCE_CASE`

### Case 3 — AI Agent 能自动完成更多任务

输入：

> 新的 AI Agent 能自动替人执行越来越多任务。

产出：

- 候选选题：**为什么 AI 越能替你做事，你反而越需要决定哪些事不能交给它？**
- Human Process：任务委托 / 控制权分配
- 反常：能力越强，本应越省心，但越需要明确权限和确认边界
- Human Tension：委托效率 vs 控制权
- AI Changed Process：AI 从“告诉你怎么做”进入“实际执行工作流”
- 主机制：工具能力与授权 / 审批边界是两个不同层次
- Meaning Fingerprint：`DELEGATION_EFFICIENCY_VS_CONTROL`
- 历史复查：旧项目历史 Registry 已存在 Agent 委托 / 权限边界的高度相近题
- 结果：`HOLD_DUPLICATE`
