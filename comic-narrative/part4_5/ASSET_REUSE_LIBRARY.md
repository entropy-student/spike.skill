# Part 4.5 — 素材库与图片复用

## 0. 文档职责

本文件是 Part 4.5 唯一正式规则文档，只定义历史图片素材的检索、复用判定、生产后入库与可追溯要求。

- Part 3 决定“画面要表达什么”；
- Part 4 决定“这一张图片如何执行”；
- Part 4.5 在执行前提供历史素材复用决策，在执行后把通过验收的新图片登记为未来可检索素材；
- Part 4.5 不修改剧本、Visual Beat、镜头意义或角色设定；
- 历史材料只保存在 `source-snapshots/045-asset-reuse/`，不参与运行；
- 迁移记录、决策过程、待办与回归结果统一记录在 `HANDOFF.md`。

Part 4.5 是双向服务层，不要求按编号线性地“跑完 Part 4 再开始 Part 4.5”。

---

## 1. 目标

长期生产中，不能默认每个 Visual Beat 都重新生成图片。

Part 4.5 的目标是：

1. 在新图片执行前检索历史已验收图片；
2. 在不改变当前 Beat 意义的前提下，优先判断是否可以直接复用、基于旧图修改或仅作参考；
3. 只有没有合适历史素材时才重新生成；
4. 把新生成并通过验收的完整图片登记进素材库，为后续 episode 提供复用候选；
5. 降低重复生图成本，同时提高角色、场景和镜头连续性。

---

## 2. 素材库的基本单位

素材库只登记**完整最终栅格图片**，不登记裁切人物、局部贴图或拼装图层。

每张可检索素材拥有一个稳定的素材编号，并至少记录：

- 素材编号；
- 文件路径；
- 文件校验值；
- 来源 episode；
- 来源 run；
- 来源 Visual Beat；
- 画面实际内容；
- 人物；
- 场景；
- 动作；
- 表情；
- 视线；
- 景别；
- POV / 摄像机关系；
- 道具 / UI；
- 时间 / 天气 / 状态；
- 因果必要文字；
- 标签；
- 当前素材状态；
- 允许的复用范围；
- 允许的复用方式。

记录必须描述**最终图片实际画出来的内容**，不能只复制计划提示词。

---

## 3. 素材状态

至少区分：

### 可复用

图片已通过当前规则要求的图片 QA，实际文件可读取，文件校验值匹配，并且已经明确允许的复用范围和方式。

### 暂停复用

包括但不限于：

- 仍待整集 / Owner 审核；
- 图片文件未正式保存；
- 文件路径或校验值不一致；
- 已知需要重做；
- 只存在本地临时文件或压缩包成员；
- 复用边界尚未确认。

暂停复用的记录可以保留用于追溯，但不能作为新的正式复用来源。

### 退役

图片已被新版本替代或不再允许复用。

历史记录不得静默删除或把原素材编号直接指向不同图片。

---

## 4. 生图前检索流程

当 Part 4 已经明确当前 Visual Beat 的画面要求后，Part 4.5 执行历史素材检索。

推荐顺序：

```text
当前 Visual Beat
→ 提取可见事件与必要物理状态
→ 搜索素材库候选
→ 打开候选完整图片
→ 做兼容性检查
→ 直接复用 / 基于旧图修改 / 仅作参考 / 重新生成
```

检索可以使用：

- 人物；
- 动作；
- 表情；
- 视线；
- 场景；
- 景别；
- POV；
- 道具；
- UI；
- 时间 / 天气；
- exact text；
- 标签；
- 连续性组；
- 状态标签。

元数据相似只能用于召回候选，不能直接证明图片可复用。

---

## 5. 复用兼容性检查

候选图片必须打开并检查至少以下项目：

- 当前 Beat 的 viewer meaning 是否一致；
- 可见事件是否一致；
- 人物身份是否一致；
- 人物集合是否兼容；
- 动作与表情是否兼容；
- POV / 摄像机位置 / 屏幕方向 / 视线是否成立；
- 场景是否兼容；
- 关键道具及数量是否一致；
- UI / 文档状态是否兼容；
- 时间、天气、昼夜是否冲突；
- 因果必要文字是否一致；
- setup / reveal 是否会提前泄漏；
- 当前 canonical Character Master / Style Reference 是否仍兼容。

不能因为“画面看起来很像”就复用。

---

## 6. 四种复用结果

### 6.1 直接复用

只有在以下必要状态都兼容时，才允许直接复用同一完整图片：

- viewer meaning；
- 可见事件；
- 人物身份；
- 人物 / 道具数量；
- POV 与物理视角；
- 场景与时间状态；
- exact text；
- withheld / reveal 状态。

直接复用不产生新的图片文件，可以让多个 Visual Beat 映射到同一完整图片。

### 6.2 基于旧图修改

选择**一张**已验收的完整旧图作为修改源。

至少要求以下内容保持兼容：

- POV family；
- camera side / crop；
- 可见人物集合；
- 主要几何；
- 人物身份；
- 关键 UI / 场景骨架。

目标只应存在一个主要状态变化。

最终仍输出一张新的完整图片。

### 6.3 仅作参考

旧图只提供明确指定的参考方面，例如：

- 人物姿势；
- 表情；
- 视线；
- 构图；
- 摄像机关系；
- 场景布局；
- UI 壳体；
- 连续性。

目标仍重新生成完整图片。

必须说明“参考什么”，不能把整张旧图当作新的故事事实。

### 6.4 重新生成

没有合适历史候选，或者候选在语义、物理状态、身份、时间、文字、reveal 等方面不兼容时，使用 Part 4 已锁定的 canonical references 和图片执行任务重新生成。

成本不能凌驾于故事正确性。

---

## 7. 禁止为了复用改变上游

Part 4.5 不得：

- 为了利用旧图修改剧本；
- 修改 Visual Beat 意义；
- 修改 POV 或镜头；
- 删除必要人物 / 道具；
- 改变关键数量；
- 把当前事件改成旧图片已有事件；
- 用旧图片错误时间 / 天气覆盖当前连续性；
- 用裁切拼装解决不兼容问题；
- 让执行 Agent 从一堆候选图里自行决定故事方向。

找不到兼容素材时，直接回到重新生成。

---

## 8. 与 Part 4 图片执行包的关系

Part 4.5 的生图前输出必须能够被写回当前图片执行任务，至少明确：

- 最终选择：直接复用 / 基于旧图修改 / 仅作参考 / 重新生成；
- 选中的素材编号；
- 来源文件与校验值；
- 参考用途；
- 必须保持的内容；
- 允许改变的主要状态；
- 不兼容原因；
- fallback。

执行 Agent 只执行已经锁定的最终决定，不重新搜索素材库、不重新选择候选。

---

## 9. 生图后入库

只有图片完成最终图片 QA 后，才进入素材库候选流程。

流程：

```text
生成 / 修改图片
→ 图片 QA
→ 最终版本确定
→ 保存完整图片
→ 计算校验值
→ 根据最终画面填写素材记录
→ 确定复用范围与复用方式
→ 素材库可检索
```

失败图、被替代图、未完成图不得标记为可复用。

每个 distinct final binary 只建立一个稳定素材记录；多个 Beat 使用同一张完整图片时，不重复保存相同二进制。

---

## 10. 复用范围

复用范围应使用最窄且真实的边界。

可采用：

- 同一 episode；
- 同一场景 / 连续性组；
- 同一角色；
- 全局。

只有真正与上下文无关的图片，才允许全局复用。

带具体 UI 文字、特定天气、特定时间、特定因果状态的图片通常应保持较窄范围。

---

## 11. 连续性组

同一对象或场景的 before / after 等多张图片可以加入同一个连续性组。

每张不同图片仍然拥有：

- 独立素材编号；
- 独立文件校验值；
- 独立状态标签；
- 独立复用权限。

连续性组只表示它们属于同一视觉状态链，不代表后一张技术上一定由前一张修改生成。

---

## 12. 素材记录与生产记录的区别

### 素材库

回答：

> 这张历史图片未来可以怎么用？

重点是：

- 图片实际内容；
- 搜索字段；
- 复用状态；
- 复用范围；
- 复用方式。

### 生产记录

回答：

> 这张图片当时是怎么产生的？

重点是：

- 执行方式；
- 来源图片；
- provider / model；
- prompt / edit instruction；
- run；
- QA；
- 最终路径与校验值；
- superseded / retry。

生产记录通过验收不等于素材自动可复用。

---

## 13. 最小第一版

第一版不建立复杂自动评分，也不要求固定数量的素材入库。

只需要做到：

1. 每次生图前可以按元数据搜索历史候选；
2. 模型打开候选图片并按本文件规则判断；
3. 输出四种结果之一；
4. 执行完成后，验收通过的新图片自动形成素材记录；
5. 下次生产可以继续检索这些素材。

不使用“相似度达到某个百分比就自动复用”的规则。

---

## 14. 当前安全原则

- 复用优先于重新生成，但正确性优先于复用；
- 完整图片优先，不建立裁切素材拼装体系；
- 历史图片不能反向定义角色身份；
- 旧图不能覆盖当前 canonical reference；
- 元数据搜索只负责找候选，最终复用必须检查实际图片；
- 没有固定复用率目标；
- 没有固定每集入库数量；
- 素材越积累，未来生成成本应逐步下降，但不以降低成本为理由牺牲故事和连续性。
