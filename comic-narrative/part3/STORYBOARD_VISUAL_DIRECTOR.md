# Part 3 — 分镜与视觉导演

本模块把已锁定剧本与 Part 2 产出的计划 SRT / 语义字幕单元转换为可执行的分镜与视觉导演方案。

---

## 1. Part 3 负责什么

Part 3 接收：
- 已锁定剧本；
- 已锁定机制 / 事实边界；
- 计划生产时间线 / SRT；
- 当前视觉风格与角色 / 世界约束。

Part 3 负责回答：

> **这一刻故事世界里发生什么？观众应该看什么？从哪里看？为什么要单独有这一张图？**

Part 3 负责：
- 戏剧层级与段落变化；
- 整集 / 段落视觉策略；
- 视觉意图；
- Semantic Shot；
- Visual Beat；
- 景别、POV、构图与视觉重点；
- 画面之间的连续、对比、并列、隐喻、蒙太奇关系；
- 单帧注意力组织 / Frame Blueprint；
- 100% 锁定口播覆盖；
- 视觉节奏映射；
- 分镜级 QA。

Part 3 不负责：
- 改写剧本事实或台词；
- 决定 TTS 语速或最终语音时长；
- 最终图片 prompt；
- 角色 / 场景 / 道具参考图绑定；
- 图片模型与执行参数；
- 最终图片文件与 Registry；
- 成片渲染。

这些属于后续模块。

---

## 2. 输入不能被导演偷偷改掉

Part 3 必须保留：
- 锁定口播文本与顺序；
- 核心机制与事实边界；
- 人物、事件、因果状态；
- 已发生 / 未发生的事实；
- 关键数量、关系、时间、天气和场景锚点；
- setup / reveal 的信息边界；
- Part 2 已确认的叙事视角入口。

禁止为了“好画”而：
- 把假设未来画成已经发生；
- 发明新人物、新行为、新结果；
- 改变故事因果；
- 把真实事件替换成抽象解释图；
- 用画面新增未经批准的可读事实。

如果剧本没有足够真实可视事件，不应由 Part 3 发明事件，应返回上游处理。

---

## 3. 当前正式工作结构

正式执行收敛为三层：

```text
锁定剧本 + 机制核心 + 计划时间线
→ 1. 整集 / 段落视觉策略
→ 2. Semantic Shot
→ 3. Visual Beat
→ Director Shotboard
```

当前三层包含：

- Semantic Shot 记录故事变化、主要视觉意图和导演级视觉策略；
- Visual Beat 记录具体画面状态、单帧注意力组织和时间字段；
- 时间字段直接绑定 Part 2 产出的 SRT / 语义字幕单元。

---

## 4. 第一硬门：这一刻故事世界里实际发生了什么

每个 Visual Beat 在进入单帧设计前必须能回答：

> **这一刻故事世界里实际发生了什么？**

至少明确：
- 谁 / 什么是行动主体；
- 实际动作或外部事件；
- 之前是什么状态；
- 之后是什么状态；
- 谁承受 / 看到后果；
- 观众必须读懂的意义。

可接受的承载方式优先是：
- 人物行为；
- 人物反应；
- 真实道具；
- 真实世界内 UI / 文件 / 消息 / 收据；
- 空间变化；
- 关系变化；
- 可观察的现实后果。

当前漫画叙事基线：

> **抽象解释图不能替代故事事件。**

禁止默认使用：
- 漂浮规则卡；
- 流程图；
- 抽象路径 / 箭头；
- 阈值板；
- 关系线；
- 分支图；
- 把手机 / AI 拟人成解释代理；
- 把口播比喻直接画成字面门、方向盘等解释符号；
- 把旁白文字可视化成 PPT。

真实设备或场景中本来存在的导航箭头、列表符号等不属于解释图禁令。

如果唯一答案是“这张图解释旁白”，返回 Part 3 重新找真实事件；如果剧本本身没有可画事件，返回 Part 2。

---

## 5. 戏剧层级（Semantic Shot 字段）

不再单独产出戏剧层级文档。设计 Semantic Shot 时记录对应的故事变化即可。

使用：
`Sequence → Scene → Beat`

- **Beat**：最小动作 / 反应 / 策略变化，不要求每个 Beat 都是重大价值转折。
- **Scene**：一串连续 Beat，产生可感知的故事 / 状态变化。
- **Sequence**：多个 Scene 形成更大的累积变化。

它只回答“故事发生了什么变化”，不决定景别、机位、构图和图片时长。

避免：
- 戏剧层级完全扁平；
- 只按句子 / SRT 条目机械切 Beat。

---

## 6. 整集 / 段落视觉策略

在逐张设计前先确定：
- 主视觉发动方式；
- 可选次视觉发动方式；
- 世界 / 场景系统；
- 0–2 个有意义的视觉母题；
- 1–3 个主要视觉构成因素；
- 视觉强度变化；
- 各 Sequence 的画面关系语法。

历史已验证的视觉发动方式包括：
- 行动 / 反应；
- 演化隐喻；
- 重复摩擦；
- 调查 / 发现；
- 关系对话；
- 过程变化；
- 对比；
- 物件驱动；
- 联想蒙太奇；
- 混合。

它们是**配置，不是新的导演流程**。

画面关系可使用：
- 连续；
- 并列；
- 蒙太奇；
- 对比；
- 隐喻；
- 插入物主导；
- 澄清。

不要求所有段落都模拟连续电影空间。

---

## 7. 视觉意图（Semantic Shot / Visual Beat 字段）

不再单独产出 Visual Intention Map。每个 Semantic Shot 记录主要意图；Visual Beat 如有必要可局部覆盖。

每个有意义的单元先决定观众此刻最需要：
- 建立环境；
- 跟随行动；
- 读反应；
- 注意物件；
- 共享人物视角；
- 感受关系；
- 看见后果；
- 经历反转；
- 接住包袱 / 回报；
- 跟踪隐喻状态；
- 比较状态；
- 建立模式；
- 澄清机制。

**先决定意图，再选镜头。**

不能因为“这个镜头看起来好看 / 有变化”反过来寻找理由。

---

## 8. Semantic Shot

Semantic Shot 是一个连贯的导演级视觉策略。

当以下任一项发生有意义变化时，可以建立新的 Semantic Shot：
- 人物行动 / 策略；
- 人物反应；
- 观众获得的信息；
- 主要人物 / 物件；
- POV；
- 人物关系 / 空间站位；
- 地点 / 世界状态；
- 隐喻状态；
- 后果 / 反转 / 回报；
- 画面关系语法；
- 所需视觉强度。

每个 Semantic Shot 至少保留：
- 对应戏剧段落；
- 主要视觉意图；
- 镜头功能；
- 主体优先级；
- 站位 / 动作关系；
- 景别策略；
- POV 策略；
- 构图策略；
- 视线 / 注意力衔接；
- 必要的空间连续规则；
- 视觉强度；
- 画面关系；
- 当前视觉状态；
- 通过条件。

Semantic Shot 不必锁死每一张子图的具体 POV / 景别。

---

## 9. Visual Beat

关系：

`Semantic Shot → 1..N Visual Beats`

Visual Beat 是最接近“一张最终完整画面”的导演单元。

每个 Visual Beat 至少锁定：
- 对应口播范围；
- 本地视觉意图；
- 这一刻实际发生什么；
- 实际景别；
- 实际 POV / 角度；
- POV 原因；
- 主要人物 / 物件状态；
- state_before / state_after；
- 主要焦点，可选第二焦点；
- 构图 / 注意力路径；
- 信息密度；
- 必要背景锚点与应压低内容；
- continuity preserve / frame delta；
- 必要 withheld information；
- 画面关系；
- 视觉强度；
- 时间线锚点与 cut / hold / handoff；
- 观众必须理解什么；
- acceptance criteria。

只有当**图像级意义发生变化**时才拆新 Beat，例如：
- setup → action；
- action → result；
- cause → meaningful reaction；
- joke setup → landing；
- 关键物件 / UI 状态变化；
- 有意义的 POV discovery；
- 隐喻状态变化；
- 比较 A → B；
- 真正产生意义的蒙太奇累积；
- 视觉强度发生必要变化。

### 不拆的情况

以下本身不自动产生新 Beat：
- SRT 新增一条；
- 旁白多了一个分句；
- 连续列举几个词；
- 想让画面“多变一点”；
- 只有手指位置 / 轻微表情 / 微小构图差异改变；
- 一张完整图已经能承载相邻口播且不会损失新的动作、因果状态、关注点或 POV。

原则：

> **Beat 数量不是配额。**

不使用固定平均秒数、固定图片数量或 SRT 条数作为 Beat 配额；优先保证 Beat economy。

---

## 10. Setup / Reveal / Reaction

当“先不让观众看到结果”本身有戏剧意义时，可以拆：
- setup；
- reveal；
- reaction。

要求：
- setup 不能提前泄露 payoff；
- reveal 必须真的新增信息；
- reaction 只有人物反应本身改变故事体验时才单独存在。

不要为了模仿动画动作过程，把一个仍可由一张完整图表达的动作拆成大量微小状态。

---

## 11. POV：从戏剧功能选择

核心问题：

> **这一刻观众应该看主人公，还是和主人公一起看？**

### 旁观
适合：
- 表情；
- 身体语言；
- 犹豫；
- 行为改变；
- 人际 / 空间关系。

### 第一人称 POV
适合：
- 阅读；
- 发现证据；
- 看具体文字 / 状态；
- 对比信息；
- 从人物经验进入 UI / 文件。

### 第一人称手部
适合：
- 人物亲手写、点、拖、签、支付、移动；
- 这个手部动作本身制造后果。

### 越肩
适合同时保留：
- 人物对动作的所有权；
- 可读的目标 / 屏幕 / 物件。

### 客观插入
适合：
- 物件 / UI 本身就是因果证据；
- 不需要人物表情。

### 关系旁观
适合：
- 两个人之间的关系 / 对话 / 空间关系是重点。

第一人称口播不意味着所有画面必须第一人称。

每次 POV 变化必须有信息 / 故事理由，不能只为视觉变化。

每个 Beat 应记录 `pov_reason`。

---

## 12. 物理视角必须成立

POV 标签正确不代表画面物理成立。

涉及可读屏幕 / 文件 / 物件与人物时，必须检查：
- 摄像机在哪里；
- 屏幕 / 纸张朝向哪里；
- 人物看哪里；
- 观众实际能看到哪一面；
- 人物是否真的能看到自己被描述为正在看的内容。

典型错误：
- 屏幕正对观众，同时人物站在屏幕后方却像在阅读屏幕正面；
- 画面要求观众同时看到互相冲突的正反两面；
- 人物目光与因果物件不在可成立的空间关系中。

如果一张图不能同时承担“看人物反应”和“读屏幕证据”，拆成相邻的 reaction / discovery Beat，前提是两者都新增意义。

物理不可能时返回，不允许靠“生成模型大概能画”放行。

---

## 13. 景别与镜头选择

景别按信息需要选择：
- 远 / 全：地点、人物关系、尺度、全身动作、世界状态；
- 中：互动、手势、任务、操作物件；
- 近：重要反应、决定、潜台词；
- 插入：因果物件、UI、证据。

不为了“镜头语言丰富”随机改变景别。

镜头优先级遵循：
1. 情绪；
2. 故事；
3. 节奏；
4. 视线；
5. 二维画面；
6. 三维连续。

高层意义可以有理由牺牲低层连续性，但不能无理由破坏。

---

## 14. 单帧字段

核心问题仍然保留：

> **观众怎样在第一眼看到这一 Beat 最重要的东西？**

Visual Beat 可使用以下单帧字段：

### 常用单帧原型
- 人物反应；
- 人物行动；
- 双主体关系；
- 物件 / 证据插入；
- 世界状态；
- 双状态对比；
- matched setup / reveal。

### 焦点
- SINGLE：一个绝对主焦点，默认；
- DUAL：两个有关系的焦点；
- FIELD：多个元素共同形成一个整体模式。

FIELD 不能只是为了塞更多信息。

### 信息密度
- LOW；
- MEDIUM；
- HIGH_JUSTIFIED。

高密度必须有叙事理由。

构图、注意力、背景压低、continuity preserve、frame delta、withheld information、acceptance criteria 均记录在 Visual Beat 中。

---

## 15. 单帧注意力与背景经济

一张画面优先级：
1. 故事动作 / 反应；
2. 主体层级；
3. 空间关系；
4. 因果道具 / UI；
5. 风格装饰。

背景只保留：
- WORLD_ANCHOR：定位世界；
- STORY_PROP：推动事件；
- 必要的角色化细节。

普通装饰不能和主要动作竞争注意力。

“简化背景”不等于所有 Beat 都在同一张桌子前。

当地点、天气、进入 / 离开、人与人距离本身有故事意义时，应保留真实空间。

---

## 16. 机制画面的优先顺序

当需要让观众理解机制时，优先依次尝试：
1. 故事后果；
2. 人物行动 / 决定 / 交接；
3. 道具或世界规则真实变化；
4. 演化隐喻；
5. POV / 真实物件 / 真实 UI；
6. 蒙太奇 / 对比；
7. 明确解释图。

在当前漫画叙事生产基线中，第 7 项不能替代真实故事事件；若没有真实事件，应回到上游，而不是生成 PPT。

---

## 17. 连续性、稳定 ID 与可辨识性

重复出现的关键元素应有稳定身份：
- 角色；
- 因果道具；
- UI shell；
- 场景；
- 关键数量。

连续性既包括“是同一个东西”，也包括“观众一眼能认出来”。

必须保护：
- 人物身份和成熟度；
- 关键服装 / 轮廓；
- 道具几何与数量；
- 场景结构；
- UI shell；
- 时间 / 天气 / 昼夜；
- 回忆与原事件的状态一致性。

变化只改变故事事件实际改变的部分。

必须防止：
- 多肢体或影响叙事的解剖错误；
- 屏幕朝向与人物阅读关系不可能；
- 回忆与既定时间 / 天气 / 场景冲突；
- 因果物件存在但视觉上不可辨认。

这些约束必须在 Part 3 / Part 4 接口中明确表达。

---

## 18. 全集视觉多样性检查

逐帧通过不代表整集通过。

在交给后续图片模块前，应连续查看整个 Shotboard，观察：
- 地点；
- 人物实际动作；
- 主要道具；
- POV；
- 屏幕是否承担意义；
- 真实世界后果是否出现。

重点检查：
- 长时间连续“坐桌前看手机”；
- 连续多个几乎相同 UI；
- 连续多个重复反应姿势；
- 每个 complication 都只通过另一张屏幕解释。

多样性不能靠：
- 无缘由换地点；
- 无缘由加配角；
- 无缘由换机位；
- 装饰背景。

应该优先让不同 complication 呈现**不同真实后果**。

---

## 19. 时间线字段

时间直接记录在 Visual Beat 中，并优先绑定 Part 2 产出的 SRT / 语义字幕单元。当前阶段不额外引入新的 Speech Unit 体系。

Part 3 可以决定：
- cut；
- hold；
- handoff；
- setup / reveal 切换；
- reaction 是否值得单独画；
- 一个口播范围由一张还是多张图承载；
- 哪些视觉锚点必须卡在特定语义位置。

Part 3 不可以：
- 发明每秒字数；
- 决定 TTS speed；
- 改 Production SRT cue；
- 为了画面方便重新写口播；
- 把历史 2.7 秒 / 张当硬规则。

如果视觉意义确实无法放入现有口播时间，返回时间模块：
`RETURN_TIMING_VISUAL_CONFLICT`。

长 hold 是人工复核信号，不是自动失败。

---

## 20. 100% 口播覆盖

所有实际口播都必须按原顺序绑定到：
- Semantic Shot；
- Visual Beat。

难画的一句话可以共享已有画面，但不能静默删除。

允许不覆盖：
- 文档标题；
- 元数据；
- 非口播制作说明。

如果漏掉实际口播：
`RETURN_SCRIPT_COVERAGE_GAP`。

---

## 21. 当前视觉风格边界

当前生产方向：
> **扁平简化漫画风**

目标：
- 角色长期稳定；
- 场景长期稳定；
- 一眼读懂故事动作；
- 适合大量静态图 / 有限动画生产；
- 单图精致度让位于跨图一致性与可读性。

不是：
- 高细节独立插画；
- Q 版 / 幼态；
- 霓虹科技感；
- PPT / 信息图。

“简化画风”不等于“简化成人物幼态”。

具体角色参考、服装、风格母版等由 Part 4 负责绑定；Part 3 只需不设计与这些已锁约束冲突的镜头。

---

## 22. 文本、UI 与可读事实

只有因果需要时才要求画面里出现可读文本。

当前规则：
- `TEXT_RENDER_MODE = NONE` 或 `IMAGE_NATIVE`；
- 不使用后期文字覆盖修复关键文本；
- 不使用 SVG / HTML / Canvas / PIL 文字；
- 不把错误文字后期“补正确”。

如果一个因果关键中文字符串必须可读，则后续成图必须逐字检查。

原生 UI 中自然存在的返回箭头、列表箭头等允许出现；禁止的是为了解释概念额外加的漂浮箭头。

Part 3 应只要求真正必要的文字，不把整集变成屏幕截图序列。

## 23. 与 Part 4 图片 / 资产模块的边界

Part 3 最终应交付：
- 每个 Beat 为什么存在；
- 实际发生的事件；
- state_before / state_after；
- 需要看谁 / 看什么；
- 景别；
- POV；
- POV reason；
- 构图与关注点；
- continuity preserve；
- 必要 withheld / reveal；
- 必要精确文字；
- 可接受条件；
- 时间线锚点。

Part 4 再决定：
- 用哪张角色 / 场景 / 道具 / UI 参考；
- 生成还是基于完整图片编辑；
- source frame；
- prompt；
- 图片模型；
- 文件路径；
- Registry；
- 图片执行 QA。

当前下游生产约束必须保留：
- 每个 Beat 最终交付是一张完整图；
- `COMPOSITE_CROP = FORBIDDEN`；
- 不裁切拼装；
- 不外部图层拼贴；
- 不后期文字覆盖；
- DERIVE_EDIT 只适用于机位、主体、主要几何和身份兼容的局部状态变化；
- 机位 / POV / 主体集合 / 主要几何改变时应重新生成；
- 不设编辑比例配额。

Part 3 不替 Part 4 选择具体执行资产，但必须给出足够语义，保证 Part 4 不需要自由猜故事意义。

## 24. 单主变化与复用边界

对连续状态 / 未来可编辑画面，尽量明确：
- 哪些元素必须保持；
- 这一张唯一主要变化是什么。

适合：
- setup → reveal；
- UI 状态变化；
- 同场景一个动作结果；
- before / after。

但“单主变化”是连续性工具，不是硬逼每张图只有一个差异。

如果新画面需要不同 POV、不同主体、不同主要空间结构，就不应伪装成原图的小改。

## 25. 图像 QA 反馈给导演的原则

后续成图 QA 应保护的是**故事意义**，不是每个像素级描述。

### 硬失败
- 观众读到错误事件；
- before / after 反了；
- 假设动作被画成已经完成；
- 关键数量 / 身份错；
- 多肢体 / 解剖错误影响故事；
- 视角物理不可能；
- 关键 UI 文字错误；
- 画面新增未批准事实；
- 回忆与已建立时空冲突；
- 抽象解释图替代真实事件；
- setup 提前泄露 reveal。

### 可记录的小偏差
在不改变事件、身份、因果、可读事实与连续性的前提下：
- 轻微景别差异；
- 无害设备外观小差异；
- 无害背景纹理；
- 不影响动作意义的手指距离；
- 不影响人物身份的轻微裁切。

不要为了修一个无意义的小细节反复付费重画。

## 26. Director 输出

正常生产输出：
1. 一份整集 / 段落视觉策略；
2. 一份 Semantic Shot → Visual Beat Shotbook；
3. 对应的人可读 Shotboard。

### 人可读 Shotboard 最少包含
- Semantic Shot ID；
- Beat ID；
- 计划时间；
- 对应口播；
- 这一刻实际发生什么；
- 故事变化；
- 最终画面状态；
- 景别；
- POV；
- POV reason；
- 视觉意图；
- 主要焦点；
- state_before / state_after；
- relation / transition；
- continuity / reveal 备注；
- acceptance criteria。

它用于调试 / 审核，不要求每集再增加一个 Owner 强制审批环。

## 27. Part 3 QA

### 故事事件
- 每个 Beat 是否有真实事件 / 状态，而不是解释旁白？
- 是否新增了剧本没有的事实？
- hypothetical 是否仍然是 hypothetical？

### Beat 经济性
- 这张图是否新增动作、结果、关注点、因果状态或必要 POV？
- 相邻画面能否由一张完整画面承载？
- 是否因为 SRT / 平均秒数而过度切图？
- setup / reaction 是否真的有意义？

### POV
- POV 是否有理由？
- POV 变化是否新增信息 / 体验？
- 摄像机、屏幕、人物目光是否物理成立？

### 单帧
- 第一眼能否看到主要故事任务？
- 是否有竞争焦点？
- 背景是否抢戏？
- 文字 / UI 是否真的必要？
- 是否泄露 reveal？

### 全集
- 是否连续太多同地点、同手机、同构图？
- complication 是否呈现不同后果？
- 多样性是否来自真实故事变化，而不是装饰？

### 连续性
- 人物、道具、UI、场景、天气、时段、数量是否稳定？
- 回忆与原事件是否一致？
- 因果物件是否足够可辨认？

### 覆盖与时间
- 口播是否 100% 覆盖？
- 是否改动口播时长 / 文本？
- 视觉意义是否能容纳在计划时间内？
