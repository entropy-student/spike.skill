## 1. 目标与成功条件

Part 3 把锁定故事变成观众可以持续看懂、愿意跟随的漫画画面规划。它同时解决两件事：整集怎样通过真实故事变化形成视觉过程；这一张完整图为什么存在、要看什么、从哪里看、停在哪个状态。

生产目标是静态漫画图 / 有限动画视频，不是摄影脚本，也不是配图讲义。不能只保证每张图“内容没错”，还要让段落之间有行动、发现、后果、关系或选择的推进；也不能为了画面热闹发明事实、配角或动作。

规划完成至少意味着：

- 锁定口播全部按原顺序得到视觉承接，机制、真实性和不确定性没有被画面改写；
- 整集 / 段落的主要视觉载体、世界与空间、强度变化和画面关系已想清楚；
- Semantic Shot 有连贯的导演策略和有意义的故事阶段变化；Visual Beat 有新增图像意义或合理的承接任务；
- 每个 Beat 可落实为一张完整静帧，景别、物理 POV、焦点、最终状态、连续性和 reveal 足够明确；
- 时间绑定可追溯，计划和真实音频的权限边界清楚；
- 分镜 QA 通过，Part 4 无需猜故事意义或重新导演。

这仅代表导演规划通过，不代表图片已经生成、角色稳定性经过实图验证、真实音频已经对齐或成片通过。

## 2. 输入、职责与不能改的事实

### 2.1 接收什么

接收 Part 2 锁定的机制核心 / 事实边界、故事前提、完整口播稿、必要语义节奏，以及当前已提供的计划 SRT / 语义字幕单元；接收长期角色与风格基线及本集已确认的世界约束。

记录剧本、计划时间资料和视觉基线的版本 / 来源。计划 SRT 可以是当前上游交付的一部分，但不因此把语速和时间估算权交给 Part 2 Writer 或 Part 3。当前沿用给定 SRT / 语义字幕单元，不另建强制 Speech Unit 体系。

如果尚无实际计划时间，可以先做标为草案的视觉策略与语义拆分；不得凭字数 / 秒数造出“正式时间”，也不得宣称时间 QA 已通过。需要完整交付时返回时间职责补齐。

### 2.2 拥有的决定

Part 3 负责整集 / 段落视觉策略、戏剧阶段与导演意图、Semantic Shot、Visual Beat、可见表演、站位、景别、POV、单帧注意力、画面关系、连续性、setup / reveal、视觉 cut / hold / handoff、口播覆盖和分镜级 QA。

它决定“画面应该表达什么和怎样看”；不选择具体历史素材、asset ID、图片路径 / hash、编辑 source、执行模式、最终 prompt、图片后端参数或 output_name。

最新正式下游分工是：同一图片规划 Agent 默认承担 Part 4 + Part 4.5 的生图前职责；执行 Agent 按锁定包生图并做逐图 / 整集结果 QA；生产后素材资格再按 Part 4.5 处理。Part 3 不为复用成本反向改事件，也不承担正常流程中的最终图片验收。

### 2.3 不可偷偷修改

保护口播文本与顺序、机制和事实边界、人物 / 关系、行动所有权、已发生与未发生、关键数量、时间 / 天气 / 场景锚点、setup / reveal 信息边界，以及 Part 2 已确认的叙事视角。

可以设计对锁定故事的视觉落实，例如怎样站、看哪里、哪个因果对象成为焦点；不能借落实新增未经支持的购买、对话、结果、真实品牌或后台证据。单图“更好画”、整集“更多样”或旧素材“更省钱”都不构成改事实的理由。

故事自身缺少事件 / 推进时回 Part 2；已有事件但导演选择单调时由 Part 3 重做视觉实现；编译或图片偏离正确规划则交下游修复。

## 3. 正式生产逻辑与最小输出

本方案保持轻量生产结构，恢复的是思考和判断，不恢复一层一个文档：

```text
锁定故事 / 机制 / 计划语义时间
→ 整集与段落视觉策略
→ Semantic Shot：故事阶段与连贯导演策略
→ Visual Beat：完整画面状态与视觉时间
→ Shotbook / 派生 Shotboard
→ 分镜 QA 与 Part 4 交付
```

戏剧层级、视觉意图、Frame Blueprint 和时间映射仍存在，分别落实在策略 / Shot / Beat 内容中。它们是不同问题，不因合并文件就省略，也不要求各自独立中间文件。

正常交付三类内容：一份视觉策略、一份嵌套 Shotbook、一个对应人可读 Shotboard。Shotbook 为机器事实入口，Shotboard 是同一内容的展示 / 审核视图，不能维护两套独立导演事实。语义输入不足时交付明确 RETURN / 草案，不以空字段或套话声称完成。

## 4. 先判断画面世界和观众知道什么

每个段落先回答：此刻发生 / 显现什么？谁行动或承受后果？观众应知道什么、暂时不能知道什么？这属于哪种叙事事实？

### 4.1 真实事件并不等于只准画现实摄影

允许的画面依据包括：

- 锁定频道故事世界内的行动、反应、空间变化、物件、真实 UI / 文件和后果；
- 上游已经建立的比喻世界内可持续发生的事件，例如工作桌累积 / 清空与笔记留下；
- 已锁定的回忆、计划、假设或主观脑补，其叙事属性在画面中可辨；
- 上游已建立或明确允许作为视觉落实、且受锁定机制支持的一般示范，其匿名 / 一般性边界清楚，不伪装为本集个案证据。

“实际发生什么”要求画面有可观察的事件或状态，而不是禁止虚构频道角色、比喻世界或主观状态。也不要求每个 Beat 都有新的物理动作：等待、setup、发现、反应或世界状态只要承担必要图像意义即可。

不能把“我怀疑平台知道我要订房”画成客观后台确实给我贴标签；如果已经锁为脑补，就明确如何与现实画面区分，不能只写“有主观气氛”让下游猜。一般客房夜晚 → 清晨可以说明房晚时效性，但不能证明主角此次涨价的具体原因。

一般示范必须受已锁机制和事实约束；机制为真不自动授权导演新增示范事件。上游未建立 / 未允许的新示范，以及需要新增故事事件、重要解释或改变叙事属性的方案，返回 Part 2 / 已有确认流程，不由导演为多样性自行扩写。

### 4.2 Anti-PPT 的准确范围

抽象流程图、漂浮规则卡、概念箭头、关系线、分支图、人格化解释代理和大段旁白字卡，不能代替故事事件。不能因为口播出现“方向盘 / 门槛”，就临时画字面符号解释概念。

真实设备内的 UI 卡片、返回箭头、导航、消息和文件允许；已成立的演化隐喻 / 主观画面也不因“不是客观现实”一概禁止。关键是有没有授权的故事规则、连续状态和观众不会误读的事实边界。

机制表达优先尝试：故事后果 → 人物行动 / 决定 / 交接 → 道具或世界规则的变化 → 已建立的演化隐喻 → 必要真实物件 / UI → 有意义蒙太奇 / 对比。若只能靠概念图解释，返回上游，不把“解释图最后考虑”理解为当前存在自动例外。

## 5. 在逐张设计前落实整集视觉策略

策略不能只列一个发动方式名、写“画面丰富”或“避免重复”。在现有策略文档内，先说清各主要段落如何通过人物、世界和物件发生变化，再设计子图。

### 5.1 发动方式与画面关系

按故事选择主要视觉发动方式，可有必要的次方式：行动 / 反应、演化隐喻、重复摩擦、调查 / 发现、关系对话、过程变化、对比、物件驱动、联想蒙太奇或混合。

这些是支持的配置选项，不是每一种都已完成独立生产验证。既有 G4R 案例直接验证了行动 / 反应、演化隐喻、重复摩擦和调查 / 发现；新配置需要明确故事理由，不需要凭空增加导演层。

段落画面关系可用连续、并列、蒙太奇、对比、隐喻、插入物主导或澄清。不把所有段落强制拍成连续电影空间，也不把非连续语法当无约束地随机换世界。

### 5.2 各段到底看什么

每个主要段落说明：故事从什么状态到什么状态；主要画面载体是什么；人物实际做什么 / 世界有什么可见后果；哪些必要信息只能由 UI / 物件呈现；与前段在哪方面重复、在哪方面产生有意义差异。

优先把已经存在的行动、空间、关系和现实后果作为正文载体。UI 承担确切报价 / 条件，反应承担人物体验，客观世界状态承担机制后果；它们不是可随机轮换的类型卡。主题确实需要证据阅读时允许连续 insert，不要求强行加入行动或地点。

例如 H019 可以围绕“等待确认 → 报价变化 → 怀疑 → 查条件 → 理解报价与条件 → 新选择”组织不同任务；本地H019下游任务已有客房夜 / 晨示范，用于库存时效。它是本方案的参考例子，采用时核对上游授权，不能仅由下游任务存在推定一般示范已获正式授权，也不把每段都转成主角再看一页UI。H015选题库的故事切口包含“不带伞 → 半路下雨 → 回看预报”；若完整锁稿保留这些事件，视觉策略应让世界后果承担判断变化，不能只让晴天图标换成雨图标。这里是策略示意，逐图仍以该集锁稿为准，不凭选题摘要补新行为。

### 5.3 强度、密度与节奏分别设计

沿用现行0–2个有意义母题、1–3个主要视觉构成因素的集中度要求，比如空间距离、画面密度、主体尺度、明暗 / 色调、对比 / 相似和注意力位置。零母题允许，不为凑数制造物件回扣。记录需要的建立、累积、转折、包袱和释放，不把每个因素同时变化；这些范围不同于图片、地点或秒数配额。

三者分开：

- **视觉强度**：情绪 / 冲突 / 信息对比有多强；
- **信息密度**：一张图有多少需要观众处理的信息；
- **视觉节奏**：状态怎样切换、停留、延迟或回扣。

强度高不等于塞很多物件，密度低也不等于故事没有变化。开头服务进入处境与好奇，关键落点给读懂 / 反应时间，结尾兑现变化；不硬套“前几秒高密、最后几秒低密”的固定模板。

### 5.4 在规划中检查连续重复

检查是否长段只有坐着看手机、另一页 UI、同一种 reaction，且没有新增行动、发现、后果或选择。明确哪些重复是调查 / 摩擦 / 喜剧的累积，哪些只是把相近解释分散到多张图。

重复有意义就保留并让差异可见；无意义时改画面承接、合并冗余图像状态或反馈剧本，不靠加场景、加配角、机械换 POV 来遮盖。没有固定镜数 / 时间窗口 / Tableau 百分比；去掉计数后仍要作出整集判断。

## 6. 世界 / Scene System：先设计用途，再谈参考图

### 6.1 两种 Scene 不混同

戏剧 Scene 是一段产生可感知故事变化的连续行动，物理 scene / location 是房间、街道或功能区。一个房间可容纳多个戏剧阶段；一个阶段也可能用并列 / 蒙太奇跨空间。不用地点数量衡量故事丰富度。

### 6.2 最小世界准备

在视觉策略中写清需要的地点 / 功能区、各自故事用途、人物和关键对象的空间关系、重要时间 / 天气 / 昼夜、何时进入 / 离开、哪些区域或对象重复出现、哪些状态允许改变。

单地点题材尤其要有变化方案：人物行为、空间占有、关系距离、道具状态、可见后果和注意力任务怎样随着故事变化。工作桌与长期笔记本例子可以始终在同一房间，靠桌面累积 → 清空、笔记仍在形成机制区分；不需要为了丰富增加四间房。

稳定 ID / 逻辑锚点与约束可在策略或 Shotbook 中引用，避免重名和每张重设。仅记录影响故事和连续性的几何，不要求写完整家具清单。

### 6.3 Scene System 不等于 Scene Master 图片库

Part 3 决定本集世界、功能区、空间 / 状态关系和重要锚点；Part 4 决定用哪些图、是否需要预生成 mini master。最新正式 Part 4 已确认“需要稳定 ≠ 必须生成独立 master”：可用 canonical 图、许可兼容旧图或本集接受早期帧。

不恢复长期固定面馆 / 工位 / UI，不要求4–8张Scene Master，也不把“单集临时参考图为0”变成目标。有没有做好场景规划，看故事用途与连续关系，不看预生成图数量。

## 7. Semantic Shot：故事阶段与连贯导演策略

用 `Sequence → 戏剧 Scene → 动作 / 反应 Beat` 理解故事变化，但不把这些术语与文件或图片数量一一对应。Semantic Shot 承载一个连贯的导演策略和有意义阶段；不是摄影学意义的一次不间断镜头。

建立新 Semantic Shot 前确认：段落结束时，人物处境、认知、关系、选择、策略或重要后果，是否发生值得标记的变化？仅新表情、新 UI、新机位或新信息不自动成立；改变理解的重要发现、转折、关系变化和策略变化可以成立。

这是 C 方案对既有结构的补强。它不要求每张图都有重大价值变化，也不禁止 reaction、setup、evidence、必要 POV discovery 单独成为子 Beat。

每个 Shot 保留故事 / 口播范围、阶段变化、主要视觉意图、镜头功能、主体优先级、站位 / 动作关系、景别与 POV 策略、构图与视线衔接、必要空间连续、关系语法、强度变化和通过条件。

视觉意图回答观众现在需要注意 / 理解 / 感受什么：建立环境、跟随行动、读反应、注意物件、共享发现、感受关系、看见后果、经历反转、接住包袱、跟踪隐喻、比较状态、识别模式或澄清机制。先意图，再表演和镜头；子 Beat 可以因局部任务覆盖意图，不能覆盖该 Shot 的事实。

连续多个 Shot 如果只是重新说“我困惑 / 我怀疑 / 这个提示不可靠”，而没有推进，先检查阶段组织是否过碎或锁稿是否重复。不能靠换远近景假装故事前进。

## 8. Visual Beat：为什么需要这张完整图

`Semantic Shot → 1..N Visual Beats`。一个 Beat 对应一个最终完整画面位置，不等于必须生成一个独特 binary；Part 4 可以让多个合法 Beat 用同一完整图，但不能改导演顺序或意义。

### 8.1 拆图条件

只有新增图像级意义时拆：setup → action / reveal，action → result，cause → meaningful reaction，喜剧铺垫 → 落点，关键 UI / 道具状态变化，新的必要视点发现，演化隐喻的推进，比较 A → B，蒙太奇累积或有叙事理由的强度变化。

SRT多一条、旁白多分句、口头列举、轻微手指 / 表情差异、想多变一点，不自动拆。一个静帧可以承接多条口播，一条口播也可以有多张图，不以平均秒数或SRT数定配额。

删除 / 合并测试：去掉这张后，是否丢了新的动作、因果状态、关注点、发现、人物体验或包袱？如果已有一张图能清楚承接且不泄露reveal，合并图像承接；保留全部口播，不借合并删台词。

### 8.2 最终静帧停在哪个状态

每个 Beat 除before / after外，还明确最终图应呈现的可见状态：准备、动作中的关键瞬间、已完成结果、等待、读到信息或反应。before / after 是因果上下文，不要求同时画进一图，也不把“先打开再惊讶再付钱”整段过程塞进一个prompt。

“已经咬下并开始咀嚼”不能画成食物仍悬在嘴前；“主角尚未发出回复”不能画主角发送成功。静帧不靠字幕、动画推拉或下游自由选择关键帧来补含义。多状态确需不同信息时拆，只有微动作则不模拟动画帧。

### 8.3 最小 Beat 内容

| 内容 | 导演阶段明确什么 |
|---|---|
| 定位 / 覆盖 | Beat ID、父Shot、顺序、原口播范围与来源锚点 |
| 意义 | 本地意图、事件 / 状态、观众必须理解什么、事实 / 主观 / 回忆 / 示范属性 |
| 静帧 | 可见人物 / 对象、最终画面状态、state_before / after、主体动作 / gaze / 表情中真正重要的部分 |
| 镜头 | 实际景别、POV / angle及原因、相机和物体朝向的必要关系 |
| 单帧 | 主焦点、可选第二焦点、构图 / 注意力、密度、背景锚点与应压低内容 |
| 跨帧 | relation / transition、continuity preserve、主要delta、withheld / reveal、回忆 / 回扣关系、局部视觉强度与所属强度弧 |
| 文字 | 因果必需字符串或已锁允许集合；不必要可读事实的边界 |
| 时间 | 给定计划时间 / 语义锚点、cut / hold / handoff、需保护的落点 |
| 验收 | 什么让观众读对 / 什么不可改变；不列无意义像素配额 |

字段名可映射，条件不适用时不要求填冗余空句。本表是信息职责，不是新增正式schema；上游已给的内容可以引用 / 继承，明确真正局部变化即可。

## 9. 表演、POV、景别与物理可行性

### 9.1 表演先于机位变化

人物不是“解释这句话的人形标记”。选择让欲望、判断、关系或后果可读的姿态、动作、视线和停顿。reaction应表现受到什么影响或如何改变下一步，不是每句之后换一个皱眉。

日常微动作可以成立，但承担不同Beat时差异要让观众辨认；不要为每个心情都强迫夸张表情，也不要列微小手指距离成为硬验收。

### 9.2 观众看人物，还是与人物一起看

| POV | 适用任务 |
|---|---|
| OBSERVER / 旁观 | 读表情、身体、犹豫、行为改变 |
| RELATIONAL_OBSERVER / 关系旁观 | 人际对话、站位、人物与对象的关系 |
| IP_POV / 主角视点 | 共享阅读、发现、关键文字 / 信息 |
| IP_POV_HANDS / 主角手部 | 主角亲手写、点、签、支付等行动所有权制造后果 |
| OVER_SHOULDER_IP / 越肩 | 同时保留行动所有权与可读目标 |
| OBJECTIVE_INSERT / 客观插入 | 物件 / 文档 / UI本身就是证据，无须脸部反应 |

每个Beat有`pov_reason`。第一人称口播不强制第一人称相机；也不能因为同一室内就全部旁观。Shot可以组织旁观 / POV混合策略，子图仍必须确定实际模式，不能留一个含混HYBRID给执行器。

POV变化必须带来信息、体验或故事理由。反应 → 看对象 → 读证据 → 回到选择可以成立；机械循环这种模式同样会单调。主角不必每张露脸，手 / 袖口 / 背影只需要适用身份线索。

### 9.3 景别和空间

远 / 全用于地点、关系、尺度、全身动作、世界状态；中用于互动和物件操作；近用于重要反应、判断与潜台词；insert用于因果对象、UI和证据。景别不随机轮换，不用“手机特写”自动替代所有机制段落。

屏幕 / 文件与人物同时出现时，说明相机在哪、物体朝向、人物看哪里、观众能看到哪一面；屏幕正对观众而角色在其背后不能同时阅读正面。无法兼顾反应与证据时，按新增意义选择越肩或相邻discovery / reaction，不期待模型解决物理矛盾。

选择取舍遵循情绪 → 故事 → 节奏 → 视线 → 二维画面 → 三维连续。这个优先级可以支持有意跳切 / 对比，不能授权错误事实、多肢体或物理不可能。

## 10. 单帧注意力、密度与阅读条件

常用单帧原型包括人物反应、人物行动、双主体关系、物件 / 证据插入、世界状态、双状态对比和matched setup / reveal。选择原型服务图像任务，不机械轮换。

默认一个明确主任务与主焦点（SINGLE）。双焦点（DUAL）必须形成有意义的关系，注意力主次或对比顺序可读，不能再添同等抢眼第三目标；通常第二焦点支持主焦点，也允许双主体关系本身成为整体主任务。FIELD用于累积、拥挤、群体等共同状态，不只是多塞东西。

让焦点通过尺度、明暗 / 色调、隔离、人物视线 / 手势、布局等获胜；背景只保留定位世界、推动事件或必要角色化细节，装饰压低。但“背景简化”不是清空所有空间，也不是让全片固定在桌前。

注意力说明进入哪、看到什么、怎样交接下一张；可以保持、handoff、重置、有意跳切或withhold→reveal，不必每张填写九宫格坐标。跨帧视线组织不是抽象箭头画在图上。

密度使用LOW / MEDIUM / HIGH_JUSTIFIED；高密度要有累积、拥挤或证据对比理由。不把视觉强度、密度、镜头切换速度合成一个分数。

规划要考虑小屏、关键文字和因果对象可辨，以及已知后续字幕位置是否遮住关键信息。可以用第一眼主焦点、缩小后可读性等经验检查；不把“1秒 / 25% / 底部15%”变成每帧硬阈值，也不因还未生图声称已通过实图测试。

普通视频字幕是后续独立视频层；它不同于在图片上补字修复UI。Part3只做必要构图避让与语义锚点，Part4仍禁止overlay修关键图片文字，最终字幕排版 / 阅读验证属于后续成片职责。

## 11. Setup / reveal、对比、蒙太奇与回扣

### 11.1 信息释放

setup仅在期待本身有戏剧 / 喜剧作用时独立，reveal真的新增信息，reaction真的改变体验。withheld不仅是“把文字删掉”：颜色、成功 / 警告图标、数量徽标、可辨物件或表情也可能提前泄露极性和结果。

明确哪些信息此刻可见、哪些要等指定语义落点；reveal强度来自状态变化，不靠额外解释标题。不要把全部setup / action / reaction固定拆成三图模板。

### 11.2 对比与蒙太奇

对比可用先后matched画面或一张完整原生画面中清楚的双主体关系。优先不丢事件和信息边界的方式；不采用历史source-crop拼装、VS标签、漂浮结论卡或后台diagram。

蒙太奇用于时间压缩、模式积累、并列、关联或比较。每一张增加观众需要的变化，口头列举不自动变镜数；不把不同时间的画面连成“同一刻发生”的伪事实。

### 11.3 重复与回扣

母题 / 构图回扣只有服务变化才使用，通常少量即可，没有每集至少几个的配额。说明它回到哪个原状态、哪些相同、人物 / 信息 / 选择怎样不同。

邻接连续性、非相邻构图回声、同一事件的回忆是不同导演关系；这些不决定图片技术source。Part4可生成新图、编辑或完整复用，仍须尊重规划语义。

## 12. 连续性、文本与风格基线

### 12.1 需要保护什么

重复关键元素有稳定逻辑身份：人物、场景、因果道具、UI壳体、数量；保护外形 / 轮廓、关键空间关系、时间 / 天气 / 昼夜与回忆锚点。状态只改变事件实际改变的部分。

明确变化与不变，不把“所有保持”机械继承到不出镜物件；客观客房insert不为满足主角连续性而强行塞主角。单主变化是连续性 / 未来兼容编辑工具，不限制独立新POV / 新空间图只能有一个差异。

关键对象需要观众认出来，而不是只在字段出现。看不见酸菜、看不清是否已发送、数量不可辨，都可能使事实正确的文字描述变成错误画面。

### 12.2 文字和品牌

只有因果必要时要求可读文本，列出确切字符串或上游允许的完整集合；如“无房 / 售罄”均合法，则保留集合，不无依据锁死一项。金额、日期、姓名、消息状态等不能为真实感编造。

Part3锁文字语义与必要性；Part4编译IMAGE_NATIVE / NONE并逐字QA。当前不使用SVG / HTML / Canvas / PIL文字、图片后期overlay或外部图层修复。真实品牌只在已确认且必要的事实中落实，不能让模型自行补logo。

### 12.3 长期3+2

当前基线继续为[主角](assets/characters/MAIN_CHARACTER_MASTER.png)、[男生朋友 / 舍友](assets/characters/MALE_FRIEND_ROOMMATE_MASTER.png)、[女生朋友 / 同事](assets/characters/FEMALE_FRIEND_COLLEAGUE_MASTER.png)三张Master，以及[双人生活互动](assets/style/STYLE_PRIMARY_TWO_PERSON_DINING.png)、[单人生活场景](assets/style/STYLE_SECONDARY_SINGLE_PERSON_DINING.png)两张Style Reference。

角色图锁身份、年龄感、比例、外形、轮廓；基础服装为默认，可按单集已锁剧情合理变化；女生不默认恋爱关系。画风锁线条、上色、人物与环境完成度、生活气质，不锁餐馆、食物、道具或动作。

目标温暖、简化、生活化的手绘叙事漫画。单图精致让位于跨图稳定、可读和生产；不把简化画风变幼态，不恢复旧固定场景、旧V1/V2描述、动作包配额或白底比例。具体Beat绑哪张参考交Part4。

## 13. 时间锚点与100%口播覆盖

### 13.1 两层覆盖都可核对

Semantic Shot的口播范围与其Visual Beat绑定，分别承接100%锁定口播并保持原顺序。用现有cue / 文本范围定位，展开核对漏项、改写、错序和重复归属；仅统计“所有cue被提到”不证明逐字覆盖。

多cue共图、一cue多图均可。后一种多个Beat可以引用同一口播cue以定位，但表示分担该段视觉承接，不是重复播出台词；需要时标具体子句或语义落点，不建立新的强制Speech Unit。标题、元数据和非口播制作说明不在覆盖目标。

口播难画就共享适合图或反馈上游，不静默删除；执行复用和调度也不得丢失锚点。

### 13.2 视觉时间与语音时间分开

Part3确定cut / hold / handoff、setup→reveal语义落点、反应是否需要独立图、一个口播范围由几张图承接。时间优先绑定给定计划SRT / 语义字幕范围，标记来源与计划状态。

语音结束、字幕结束、既有语义停顿窗口不同。画面可在已有静默窗口hold，不要求字幕跟着覆盖静默，也不由Part3新加停顿时长。

长hold是阅读 / 节奏复核信号，不自动失败；检查此时观众在读什么、等待什么、是否仍有信息任务。短图要足以读到关键事实。不能只为改善秒数统计新增图，也不为画面方便调TTS速度、改cue或重写口播。

同一cue内部需要reveal而精确时间尚无依据时，保留语义位置与计划性，交后续对齐；不伪造毫秒精度。真实TTS后常规绝对切点变化属于时间重算，只要事件、reveal与锚点保持，不自动重新导演。

若必要视觉状态无法容纳在给定时间或后续时间调整会破坏意义，返回时间 / 上游职责协商；Part3不靠假语速自行解决。历史5.9字/秒、2.7秒中位只是来源证据，不是当前授权。

## 14. 输出合同与Part4交接

### 14.1 唯一机器入口

Shotbook沿用`semantic_shots[]`；每个Shot的`visual_beats[]`直接放完整对象，不另维护顶层Beat副本。保留唯一ID、父子关系、顺序、上游版本与口播 / 时间锚点。旧单文件schema不是整包正确性的充分证明。

视觉策略说明段落发动方式、世界 / 功能区、主要载体、现实后果 / 行为变化、母题、强度与关系；Shotbook落实到具体Shot / Beat。Shotboard由同一内容展开，至少展示Shot/Beat、计划时间、口播、阶段变化、事件和最终静帧、景别/POV/reason、意图、焦点、before/after、关系、连续性/reveal及验收。

这不要求新增分布报表、Scene Bible、Frame Blueprint文件、复杂评分或另一个Review Agent；需要审核时现有三个产物足以定位。

### 14.2 给下游足够语义

Part4应能从Beat知道实际出镜什么、图像状态是什么、如何看、必须保留什么、何时揭示、哪些文字必要以及怎样验收；不用它从口播发明事件。

Part3提供逻辑角色 / 场景 / 对象及关系；Part4 + 4.5图片规划Agent决定实际reference、资产许可、GENERATE / DERIVE_EDIT / exact reuse、source、prompt、hash、依赖和fallback。多个Beat共享binary不等于合并Beat；同一场景/回扣关系不等于可以技术派生。

当前每个Beat交付完整图，不裁切拼装、外部图层或后期补图片文字；视点、主体或主要几何变化时不能为省钱假装旧图局部编辑。Part3可以规划状态兼容关系，但不锁具体编辑方式或比例。

## 15. 分镜QA：先全局、再局部、再连续核对

### 15.1 策略QA在细分前

故事有没有可视行动 / 世界 / 关系 / 后果；主要段落的载体和变化是否具体；Scene System是否足够支撑连续与非连续语法；预期的重复是否在推进；机制是否仍然准确且不确定性保留。

若策略仅写“人物看手机+多种景别”，不因每张可填字段而放行；先解决总体规划，再逐张设计。也不因只有一处地点而失败。

### 15.2 Shot / Beat QA

- 阶段变化有意义，未把机位或小表情当新故事阶段；
- 每图新增或承接必要信息，setup / reaction / insert不是配额；
- 最终静帧明确且可执行，before / after与假设 / 已完成状态正确；
- 意图先于镜头，POV有理由，屏幕 / gaze / 相机可同时成立；
- 主要对象可辨、无竞争焦点，密度有理由，关键图文有阅读空间；
- 信息释放不从字、图标、颜色、表情或物体提前泄露；
- 身份 / 关系 / 世界 / 时间 / 天气 / 数量的变化有根据；
- 口播和计划锚点覆盖、顺序、父子结构完整，无执行字段越权。

### 15.3 整体连续查看

按播放顺序查看Shotboard：故事阶段递进、各段画面任务差异、真实后果、空间与注意力变化、回忆 / 回扣、setup→reveal和时间是否成立。检查计划与逐图落实有没有偏离，不等到成图才看整集。

若发现重复，判断是有意积累、导演冗余还是上游故事重复；分别保留其意义、调整导演承接或反馈Part2。不得随机换地点 / 人物 / 机位掩盖。

Part4成图后的整集QA负责验证规划有没有被实现：原规划不足回Part3，编译错误回图片规划Agent，成图偏离按执行合同修复。Part3不在末端接管常规逐像素图片QA，也不因图片失败默认重开已正确故事。

反馈按故事意义判断：错误事件、反向before/after、假设变事实、身份 / 数量 / 关键文字错误、多余肢体 / 影响叙事的解剖错误、物理不可能、重要时空冲突或提前泄露属于硬失败；不影响事件、身份、因果、阅读和连续性的轻微景别、设备外观、背景纹理、手指距离或人物裁切可记录。下游不能用“小偏差”放过错误意义，也不为无害细节反复付费重画。
