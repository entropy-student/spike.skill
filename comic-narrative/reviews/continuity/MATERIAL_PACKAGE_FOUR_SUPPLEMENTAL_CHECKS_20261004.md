# 素材包批量产出｜四项补充复查要求

> 来源：2026-10-04 Owner 对话确认。
>
> 性质：后续批量生成素材包时固定遵循的补充复查项。
>
> 边界：当前尚未并入 Part 3 / Part 4 正式正文；若后续要正式落入 canonical 规则，需另行修改对应项目文件。

## 1. Scene System / 场景系统

- 不能只列物理空间，还要检查剧情 Scene / 状态阶段是否充分。
- 同一物理地点可以承载多个不同剧情 Scene。
- 重点检查人物行为、关系、POV、道具状态、现实后果是否产生有意义变化。
- 不为了满足历史数字经验机械新增地点或配角。
- 若整片长期停留在同一种空间状态 / 视觉载体，应在 Part 3 阶段修正。

## 2. 单图停留时长

- 项目不恢复固定“每张图必须几秒”的硬规则。
- 长 hold 必须人工复核。
- 如果一张图实际承载两个或更多独立视觉意义，应拆成不同 Visual Beat。
- 不能因为没有固定秒数上限，就直接放过明显过长且内部发生意义变化的单图。

## 3. 高频临时角色一致性

- 对单集反复出现、连续性重要、漂移风险高的临时角色，必须先判断是否需要 episode-local Mini Master / 角色参考图。
- 若需要，应在正式批量生图前先生成并通过 QA，再作为后续角色身份锚点。
- 一次性、低连续性角色不强制建立 Mini Master。
- 角色参考图用于保证身份一致性，不得反向新增剧本没有的人物设定。

## 4. 完成前跨模块整体复查

每个素材包在认定“完成”前，必须重新对照当前项目正式要求复查，至少覆盖：

- Part 2 / Part 2.5 上游文本与时间来源；
- Part 3 Scene System、Semantic Shot、Visual Beat、事实边界与连续性；
- Part 4 Asset Manifest、Reference、执行方式、依赖、fallback、QA 与执行包完整性；
- Part 4.5 历史素材检索与复用兼容性；
- 当前 imagegen 执行合同与输出要求。

不能只检查“图片数量、提示词是否齐全”就认定素材包完成。

## 批量产出固定检查清单

```text
[ ] Scene System 不只是物理地点，剧情状态变化充分
[ ] 所有长 hold 已人工复核，必要时拆 Beat
[ ] 高频临时角色已判断是否需要 Mini Master
[ ] 完成前已按当前项目要求做跨模块整体复查
```
