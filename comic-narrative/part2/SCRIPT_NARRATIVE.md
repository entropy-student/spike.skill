# Part 2 — 剧本与叙事

本模块把已经通过选题阶段的题目转化为机制核心、故事前提和最终口播稿。

---

## 1. Part 2 负责什么

Part 2 接收已经通过选题阶段的题目，把它变成：

1. 清楚且有边界的机制核心；
2. 能独立成立的故事；
3. 自然、可直接说出口的最终口播稿。

Part 2 负责：
- 机制 / 知识核心；
- 故事前提与因果结构；
- 人物欲望、行动、阻力、后果、转折、收束；
- 观点如何从故事结果中产生；
- 第一人称 / 第三人称叙事关系；
- 口语文案、对白、潜台词、幽默、节奏提示；
- 最终剧本文本质量检查。

Part 2 不负责：
- 最终 SRT 时间戳；
- 镜头与分镜；
- 图片资产与生图提示；
- 配音；
- 成片执行。

---

## 2. 输入不能被剧本偷偷改掉

进入剧本前，先锁定“到底要讲懂什么”。

至少明确：
- 一个核心概念；
- 一个核心机制；
- 关键事实；
- 常见误解；
- 机制的边界：什么能推出，什么不能推出；
- 不确定性；
- 对普通人的实际意义；
- 来源 / 证据边界。

默认一条内容只承担一个核心机制。

如果事实不清楚、概念混杂、因果依据不足，应先返回研究，不允许靠故事把事实补圆。

Writer 可以改变表达方式，但不得静默改变：
- 已锁定的机制；
- 关键事实；
- 证据边界；
- 主角的核心欲望；
- 已锁定的因果故事骨架；
- 转折真正表达的意义；
- 已确定的内容任务 / 编辑模式。

---

## 3. 先把机制变成“故事里的世界规则”

故事不是给定义套一层人物皮肤。

机制必须真正改变事件结果。

最低因果结构：

```text
人物想得到某个具体东西
→ 出现触发事件
→ 人物采取第一次行动
→ 现实与预期出现落差
→ 困难 / 后果逐步变化
→ 出现真正的转折
→ 人物理解了之前没看见的规则
→ 做出新的选择 / 获得结果
```

故事通过至少需要满足：
- 主角真的想要什么，而不是负责听课；
- 第一次行动来自人物自己的欲望或性格；
- 核心机制会改变事件结果；
- 至少出现一次“我以为会 A，结果却 B”；
- 后续困难不能只是同一种麻烦重复三遍；
- 术语全部删掉后，故事因果仍然成立；
- 结局来自人物选择与机制后果，不是旁白突然总结。

原则：

> **保留因果，不保留公式。**

不要求固定三幕、固定分钟转折、固定高潮规模，也不能为了“结构完整”硬制造冲突。

---

## 4. 每一段都要让故事状态发生变化

一个有意义的段落 / 节拍至少要回答大部分问题：

1. 人物现在想要什么？
2. 他做了什么？
3. 世界、他人或机制怎么回应？
4. 结果和预期哪里不一样？
5. 什么东西发生了变化？
6. 这个变化为什么会逼出下一步？

有效变化包括：
- 知道了新东西；
- 目标改变；
- 策略改变；
- 风险 / 代价改变；
- 关系改变；
- 情绪改变并实际影响下一步行为；
- 可选择的路变多或变少。

优先：

> 因为 → 但是 → 所以 → 结果

而不是：

> 然后 → 然后 → 然后

删除测试：

> 如果删掉这一段，下一段仍然同样成立，人物没有新的决定，局面也没有变难、变清楚、变奇怪或变得更有后果，这一段大概率应该删掉或合并。

---

## 5. 两种故事发动方式

### 5.1 事件驱动

适合机制会造成实际外部后果的题，例如：
- 钱；
- 权限；
- 自动执行；
- 工作；
- 社交后果；
- 不可轻易撤回的动作。

基本关系：

```text
行动
→ 后果
→ 新行动
→ 新后果
→ 理解
```

历史 Agent Case 已验证这种方式。

### 5.2 比喻驱动

适合比较抽象、难直接看到的认知边界，例如：
- 上下文；
- 记忆；
- 注意力；
- 抽象系统限制。

比喻不能只出现一次然后开始讲课。

它本身必须能够连续发生事情：

```text
比喻世界里的状态变化
→ 人物行动
→ 新后果
→ 再改变状态
→ 最终自然显露真实机制
```

历史“办公桌 / 长期笔记本”Case 已验证这种方式。

### 5.3 不允许把某一种剧情模板固化

真正可复用的是：

```text
人物欲望
→ 人物行动
→ 机制回应
→ 有意义的状态变化
→ 下一次选择
→ 理解 / 结果
```

不要求每期都必须：
“犯错 → 灾难 → 矫枉过正 → 折中”。

---

## 6. 观点不能先于故事

写观点前，先有一个开放问题。

它不能是把答案改写成问句。

例如，不先决定：

> “越自动化，人越应该控制它。”

而先问：

> “当系统真的开始替你行动以后，什么事情还应该由你自己决定？”

如果一条内容需要表达观点：

```text
事实 / 事件
→ 机制
→ 两种都说得通的力量发生冲突
→ 故事后果
→ 最终选择 / 结果证明意义
→ 旁白最多轻轻点明
```

要求：
- 观点来自已锁定的事实和机制；
- 相反方向必须真的有道理，不设一个稻草人；
- 一条内容默认 0 或 1 个主要观点；
- 不从一个故事直接推成“所有人 / 整个行业 / 未来一定”；
- 有重要例外时给边界；
- 删除显性观点后，故事和机制本身仍然值得看。

原则：

> **故事先证明，旁白再轻轻命名。**

禁止：
- 先有结论，再挑故事证明；
- 反复重述主题；
- 强行“升华”；
- 突然站上讲台总结人生。

---

## 7. 角色与叙事视角

当前 Bilibili 编辑基线默认：

> **固定的第一人称频道角色，是观众进入故事的入口。**

推荐关系：

```text
我想要 / 我尝试 / 我选择
→ 世界和机制回应
→ 局面变化
→ 我反应 / 修正
→ 观众认出自己也遇到过同一种问题
```

视角入口：
- 第一人称亲历：默认；
- 旁观 / 听说：仅在明显更自然、更有戏或更符合真实性边界时建议使用；
- 若建议旁观 / 听说，不得自动切换，必须先由 Owner 确认，再锁定 StoryPremise；
- 未获确认时继续使用默认亲历；
- 第二人称只少量用于邀请观众代入或把问题重新交还给观众。

重要真实性边界：
- 频道角色可以是明确的虚构 / 风格化人物；
- 不能伪造现实中的亲身购买、任职、亏钱、测试、真实经历；
- 虚构模拟必须让观众能看出它是频道故事世界，而不是冒充真人经历。

角色不是知识主持人。

已验证的角色倾向：
- 好奇；
- 喜欢折腾新技术；
- 有点想偷懒、省事；
- 容易对新能力过度乐观；
- 遇到反噬会吐槽；
- 愿意修正自己；
- 不从答案终点出发。

长期世界观建议是：
> **固定演员班底 + 半固定世界。**

可以复用人物、关系、常驻地点和道具，但不强制所有故事发生在同一地点或同一种隐喻世界。

## 8. 剧本表面应该是什么感觉

目标不是让观众感到“结构很专业”，而是：

> **像一个聪明但不端着的人，在讲一件自己真的卷进去的事。**

表面：
- 轻松口述；
- 具体人和具体事件优先；
- 有真实反应；
- 长短句自然混合；
- 允许轻微吐槽、自嘲、荒诞感；
- 抽象判断后置；
- 技术知识从故事结果里自然长出来。

观众不应该明显感到：
- 三幕结构；
- 写作理论术语；
- “下面总结观点”；
- 第一、第二、第三；
- 教科书 / PPT / 演讲稿。

“景岁式轻盈”只作为表面气质参考：
- 不复制原句；
- 不复制角色；
- 不复制笑点；
- 不复制具体镜头。

结构规则应该藏在骨架里。

---

## 9. 开头规则

不开场自我介绍，不先讲背景百科。

优先两种开头：

### 9.1 事件 / 反常开头

直接出现：
- 异常事件；
- 意外结果；
- 奇怪决定；
- 矛盾。

### 9.2 欲望 / 冲突开头

人物可以直接说自己想做什么、讨厌什么，但冲突必须马上出现。

开头自检：
1. 第一两句里有没有具体人的处境？
2. 有没有矛盾、未知或好奇？
3. 完全不知道技术名词的人，会不会还想听下一句？

目标至少 2 项成立。

Hook 必须来自真实故事，不允许为了点击制造一个正文不兑现的问题。

---

## 10. 先让观众形成直觉，再说术语

默认顺序：

```text
具体事件
→ 第一次预期落差
→ 后果继续变化
→ 观众开始自己理解
→ 转折
→ 再说技术名 / 机制名
→ 最少量必要解释
→ 故事结果
```

不要在观众还没看懂“问题是什么”之前连续解释一堆术语。

术语不是禁用，而是：

> **只有在命名能增加理解时才出现。**

机制解释是最容易突然变成讲课的地方。

优先使用：
- 两句话的对比；
- 人物动作；
- 故事里已经出现的物件 / 状态；
- 前面建立好的比喻。

准确允许时：

> **两句对比，优先于三段定义。**

只补“故事自己还没有证明、但准确性又必须说明”的那一点。

---

## 11. 一段口播最好承担什么

有效口播主要承担六类功能之一：
- 新事件 / 新动作；
- 行动造成的后果；
- 人物反应；
- 预期被打破；
- 人物理解发生变化；
- 结局兑现。

纯解释只能作为这些东西之间的桥。

如果连续大量出现纯解释，说明故事正在变成讲解稿。

抽象信息尽量附着在：
- 一个已经发生的事件；
- 一个动作；
- 一个物件；
- 一个后果；
- 一个角色反应。

禁止：

```text
故事结束
→ 开始上课
```

---

## 12. 口语、对白与潜台词

文案必须能直接说出来。

优先：
- 一个句子一个主要意思；
- 代词对象清楚；
- 专有名词首次出现时顺手解释；
- 抽象名词不要连续堆叠；
- 长短句自然变化。

降权表达：
- “首先 / 其次 / 最后”；
- “本质上”；
- “归根结底”；
- “真正的问题是”；
- “很多普通人的问题是”；
- “你需要的是”；
- 大段定义式排比。

### 12.1 重要台词最好是在“做事”

一句重要对白 / 旁白最好在完成某个动作，例如：
- 试探；
- 施压；
- 回避；
- 解释自己；
- 讨价还价；
- 夺回控制；
- 做决定；
- 揭示；
- 反转。

不要仅仅因为“这句话把观点说得很准确”就留下它。

### 12.2 保留潜台词

如果动作、上下文、表情或下一步选择已经能让观众看出人物感受，就不要再说：

> “我特别开心。”
> “我突然很难过。”
> “我这才意识到……”

优先：

```text
事情发生
→ 反应 / 停顿 / 动作
→ 观众自己读出来
```

### 12.3 角色要有自己的语言来源

固定的不是口头禅，而是角色看世界时自然会调用的比喻来源和词汇世界。

历史当前角色常用来源包括：
- 自动化；
- 外包；
- bug；
- 退货；
- 审批；
- 插件；
- 成本；
- 偷懒；
- 上班 / 工位。

这些不是每期必用。

### 12.4 句子经济性

优先删掉：
- 只暴露结构的过渡句；
- 动作已经表现出来的情绪标签；
- 后面又会证明一次的总结；
- 重复的结论；
- “后来我想了想 / 接下来 / 最后我发现”式纯提纲标记。

测试：

> **如果下一句已经能让观众自己得出结论，这一句总结优先删。**

---

## 13. 动作、停顿、句尾和排版

真正的反转或转折处：
- 一个动作；
- 一次短停顿；
- 一句很短的话；

有时比另一段解释更有效。

停顿不能装饰性乱用，必须对应真实的故事状态变化。

部分反转 / 包袱可以把关键词放在句尾，让结果落下来。

剧本文本允许少量用排版表达语义节奏，例如：
- 单独一行的结果；
- 有意义的重复短句；
- 延迟出现的最后一个词。

但如果每段都强调，强调就失去意义。

---

## 14. 幽默规则

幽默来自：
- 人物反应；
- 荒诞后果；
- 人物习惯；
- 能连续运转的比喻。

不设笑点配额。

历史倾向：
- 一篇优先一个主梗；
- 最多再带一个副梗；
- 但这不是硬指标。

笑点不能：
- 引入未经核验的事实；
- 打断因果；
- 把角色写成只会吐槽的人；
- 为了“网感”强塞很快过期的梗。

“轻盈”不等于“必须搞笑”。

## 15. 两种编辑模式

内容的“业务任务”和“怎么讲”是两条不同轴。

### 15.1 故事理解型

```text
故事
→ 机制自然显现
→ 形成一个新的理解 / 判断
→ 可选的、有边界的观点
```

主要价值是让观众真正看懂。

### 15.2 故事行动型

```text
故事
→ 机制自然显现
→ 形成理解
→ 一个稳定、可迁移的判断规则 / 行动
```

不是每条都必须给方法。

方法只有同时满足以下条件才加入：
1. 直接来自这一期的核心机制；
2. 相对稳定，有依据；
3. 不需要再塞入第二个无关机制；
4. 自然解决或延伸故事中的问题；
5. 足够小，不会把视频变教程；
6. 会真正改变判断或行为。

优先方法形式：
- 一个判断规则；
- 一个分类规则；
- 一个诊断问题；
- 一个边界 / 风险规则。

否则用一个好的理解收束即可。

已删除的旧模式：
- 独立“教程型”不再作为第三种编辑模式。

---

## 16. 内容任务

历史内容系统保留三种主要业务任务：
- 发现：更强调陌生人能看懂的处境、异常、好奇和推进；
- 信任：更强调机制边界和真正理解；
- 解决：题目本身天然靠近行动 / 工具 / 方法时使用。

一条内容可以有次要作用，但只选择一个主要任务。

业务任务不能破坏故事和事实：
- 不能为了转化硬塞产品；
- 不能为了“实用”强塞方法；
- 没有自然下一步时可以干净结束；
- 不强制行动号召。

---

## 17. Bilibili 当前编辑基线

当前历史基线：
- 主平台：Bilibili；
- 标准时长目标：3–5 分钟；
- 更长只在叙事确实需要时使用；
- 不能为了凑时长加解释；
- 日更是编辑目标，但生产吞吐能力历史上尚未被证明。

重要：
历史 70–85 秒三篇稿只用于 Writer 能力验证，不再是当前标准时长。

3–5 分钟也不是字数配额：

> **故事自然讲完优先于填满时长。**

长内容仍然必须靠：
- 新行动；
- 新后果；
- 新选择；
- 新理解；
- 新变化；

继续推进，而不是靠解释拉长。

## 19. 最终剧本检查

### 19.1 故事
- 主角有没有一个具体欲望？
- 第一次行动是不是人物自己做出来的？
- 有没有明确预期落差？
- 困难 / 后果是不是在变化，而不是重复？
- 重要段落是否真的改变故事状态？
- 有没有一个有意义的转折、选择或结果？
- 开头的问题最终有没有兑现？

### 19.2 机制
- 核心机制有没有被改写？
- 有没有新增未经支持的事实？
- 故事里的因果是否真的由机制推动？
- 技术名词是不是只在有帮助时出现？
- 机制解释有没有突然变成讲课？

### 19.3 观点
- 内部开放问题是否清楚？
- 如果有观点，相反方向是否真的被呈现？
- 观点是否由后果和选择挣出来？
- 是否过度泛化？
- 是否强行升华？

### 19.4 口语
- 像人在讲事情，还是像报告？
- 具体人和事件是否多于抽象解释？
- 是否重复解释已经演出来的东西？
- 重要台词是否在做事？
- 情绪是否被过度直接说出来？
- 角色是否仍然像同一个人？
- 幽默是否自然？
- 有没有 PPT / 演讲腔？

### 19.5 节拍
- 每段是否新增事件、后果、信息、判断或反转？
- 有没有可以整段删除而不影响下一段的内容？
- 是否连续堆叠纯解释？

### 19.6 行动方法
- 方法是否真的来自机制？
- 是否稳定、可迁移？
- 是否为了“有用”硬加？
- 是否把结尾变成编号教程？

## 20. 常见返回原因

出现以下情况应返回修剧本，而不是继续往分镜推进：

- Writer 改变了锁定机制 / 事实；
- 故事变成讲解稿；
- 开头过于被动；
- 比喻只是装饰，不能推动事件；
- 对白太直白，把观众已经看懂的东西又说一遍；
- 机制解释变成长篇讲课；
- 方法是后来硬接上去的；
- 观点越界或过度泛化；
- 排版 / 强调过多；
- 故事太重，像培训案例；
- 同一观点换几种说法反复重复。

## 21. 与后续模块的边界

Writer 可以标注：
- 正常；
- 加速推进；
- 包袱铺垫；
- 包袱落点；
- 反转；
- 反应；
- 收尾；
- 有意停顿。

这些只是语义节奏意图。

后续时间轴模块再把它转换成正式时间。

### 下游 SRT 最小合同

- 语义节拍单元、TTS 单元、字幕单元相互独立，不要求一一对应；允许一对多 / 多对一。
- 计划 SRT 只用于生产规划；最终 SRT 以真实 TTS / 对齐结果为准。
- 字幕切分优先级：**完整意义 > 对话轮次 > 戏剧落点 > 阅读长度 > 标点**。
- 不拆词、专名、数字与单位、成对引号；不允许孤立标点 / 引导词；普通信息不得连续碎切，极短字幕只留给明确的包袱、反转、反应或强调。
- 语音结束、字幕结束、节拍 / 停顿窗口结束分开处理；字幕默认不覆盖后续静默。
- 最终字幕 QA 至少检查：孤立标点、拆词、单字行、引号不配对、多人对白粘连、显示过短、两行严重失衡。

禁止：
- Writer 自己用固定“每秒多少字”决定生产时间；
- Writer 猜时间戳并覆盖后续时间系统；
- 先生成配音，再把剧本/SRT日常性地二次创作重写。

分镜、镜头、画面视角属于 Part 3，不由 Part 2 决定最终画面。

## 22. 核心原则

> **先锁清楚要讲懂的机制，再让一个有欲望的人物真正卷进问题；人物每次行动都让机制产生后果，后果逼出下一次选择，直到关键变化让观众自己看懂规则。抽象解释后置，术语在直觉形成后再出现；角色始终是当事人而不是老师，对白和口语尽量靠动作、反应、潜台词与具体细节推进。观点和方法都不是必需品，只有故事和机制自然挣出来时才加入。最终剧本应该独立值得听完，同时不改变事实、不越过后续分镜与时间轴的职责。**
