# Part 2 — 剧本与叙事

本模块把已经通过选题阶段的题目转化为机制核心、故事前提和最终口播稿。

---

## 1. Part 2 负责什么

Part 2 接收已经通过选题阶段的题目，把它变成：

1. 清楚且有边界的机制核心；
2. 能独立成立的故事；
3. 自然、可直接说出口的最终口播稿。

Part 2 负责：
- 机制 / 知识核心；
- 故事前提与因果结构；
- 人物欲望、行动、阻力、后果、转折、收束；
- 观点如何从故事结果中产生；
- 第一人称 / 第三人称叙事关系；
- 口语文案、对白、潜台词、幽默、节奏提示；
- 最终剧本文本质量检查。

Part 2 不负责：
- 最终配音音频；
- 最终 SRT 时间戳与真实音频对齐；
- 镜头与分镜；
- 图片资产与生图提示；
- 成片执行。

最终配音与正式 SRT 对齐由 Part 2.5 完成。

---

## 2. 输入不能被剧本偷偷改掉

进入剧本前，先锁定“到底要讲懂什么”。

至少明确：
- 一个核心概念；
- 一个核心机制；
- 关键事实；
- 常见误解；
- 机制的边界：什么能推出，什么不能推出；
- 不确定性；
- 对普通人的实际意义；
- 来源 / 证据边界。

默认一条内容只承担一个核心机制。

如果事实不清楚、概念混杂、因果依据不足，应先返回研究，不允许靠故事把事实补圆。

Writer 可以改变表达方式，但不得静默改变：
- 已锁定的机制；
- 关键事实；
- 证据边界；
- 主角的核心欲望；
- 已锁定的因果故事骨架；
- 转折真正表达的意义；
- 已确定的内容任务 / 编辑模式。

---

## 3. 先把机制变成“故事里的世界规则”

故事不是给定义套一层人物皮肤。

机制必须真正改变事件结果。

最低因果结构：

```text
人物想得到某个具体东西
→ 出现触发事件
→ 人物采取第一次行动
→ 现实与预期出现落差
→ 困难 / 后果逐步变化
→ 出现真正的转折
→ 人物理解了之前没看见的规则
→ 做出新的选择 / 获得结果
```

故事通过至少需要满足：
- 主角真的想要什么，而不是负责听课；
- 第一次行动来自人物自己的欲望或性格；
- 核心机制会改变事件结果；
- 至少出现一次“我以为会 A，结果却 B”；
- 后续困难不能只是同一种麻烦重复三遍；
- 术语全部删掉后，故事因果仍然成立；
- 结局来自人物选择与机制后果，不是旁白突然总结。

原则：

> **保留因果，不保留公式。**

不要求固定三幕、固定分钟转折、固定高潮规模，也不能为了“结构完整”硬制造冲突。

---

## 4. 每一段都要让故事状态发生变化

一个有意义的段落 / 节拍至少要回答大部分问题：

1. 人物现在想要什么？
2. 他做了什么？
3. 世界、他人或机制怎么回应？
4. 结果和预期哪里不一样？
5. 什么东西发生了变化？
6. 这个变化为什么会逼出下一步？

有效变化包括：
- 知道了新东西；
- 目标改变；
- 策略改变；
- 风险 / 代价改变；
- 关系改变；
- 情绪改变并实际影响下一步行为；
- 可选择的路变多或变少。

优先：

> 因为 → 但是 → 所以 → 结果

而不是：

> 然后 → 然后 → 然后

删除测试：

> 如果删掉这一段，下一段仍然同样成立，人物没有新的决定，局面也没有变难、变清楚、变奇怪或变得更有后果，这一段大概率应该删掉或合并。

---

## 5. 两种故事发动方式

### 5.1 事件驱动

适合机制会造成实际外部后果的题，例如：
- 钱；
- 权限；
- 自动执行；
- 工作；
- 社交后果；
- 不可轻易撤回的动作。

基本关系：

```text
行动
→ 后果
→ 新行动
→ 新后果
→ 理解
```

历史 Agent Case 已验证这种方式。

### 5.2 比喻驱动

适合比较抽象、难直接看到的认知边界，例如：
- 上下文；
- 记忆；
- 注意力；
- 抽象系统限制。

比喻不能只出现一次然后开始讲课。

它本身必须能够连续发生事情：

```text
比喻世界里的状态变化
→ 人物行动
→ 新后果
→ 再改变状态
→ 最终自然显露真实机制
```

历史“办公桌 / 长期笔记本”Case 已验证这种方式。

### 5.3 不允许把某一种剧情模板固化

真正可复用的是：

```text
人物欲望
→ 人物行动
→ 机制回应
→ 有意义的状态变化
→ 下一次选择
→ 理解 / 结果
```

不要求每期都必须：
“犯错 → 灾难 → 矫枉过正 → 折中”。

---

## 6. 观点不能先于故事

写观点前，先有一个开放问题。

它不能是把答案改写成问句。

例如，不先决定：

> “越自动化，人越应该控制它。”

而先问：

> “当系统真的开始替你行动以后，什么事情还应该由你自己决定？”

如果一条内容需要表达观点：

```text
事实 / 事件
→ 机制
→ 两种都说得通的力量发生冲突
→ 故事后果
→ 最终选择 / 结果证明意义
→ 旁白最多轻轻点明
```

要求：
- 观点来自已锁定的事实和机制；
- 相反方向必须真的有道理，不设一个稻草人；
- 一条内容默认 0 或 1 个主要观点；
- 不从一个故事直接推成“所有人 / 整个行业 / 未来一定”；
- 有重要例外时给边界；
- 删除显性观点后，故事和机制本身仍然值得看。

原则：

> **故事先证明，旁白再轻轻命名。**

禁止：
- 先有结论，再挑故事证明；
- 反复重述主题；
- 强行“升华”；
- 突然站上讲台总结人生。

## 7. 角色与叙事视角

当前 Bilibili 编辑基线默认：

> **固定的第一人称频道角色，是观众进入故事的入口。**

推荐关系：

```text
我想要 / 我尝试 / 我选择
→ 世界和机制回应
→ 局面变化
→ 我反应 / 修正
→ 观众认出自己也遇到过同一种问题
```

视角入口：
- 第一人称亲历：默认；
- 旁观 / 听说：仅在明显更自然、更有戏或更符合真实性边界时建议使用；
- 若建议旁观 / 听说，不得自动切换，必须先由 Owner 确认，再锁定 StoryPremise；
- 未获确认时继续使用默认亲历；
- 第二人称只少量用于邀请观众代入或把问题重新交还给观众。

重要真实性边界：
- 频道角色可以是明确的虚构 / 风格化人物；

角色不是知识主持人。

已验证的角色倾向：
- 好奇；
- 喜欢折腾新技术；
- 有点想偷懒、省事；
- 容易对新能力过度乐观；
- 遇到反噬会吐槽；
- 愿意修正自己；
- 不从答案终点出发。

写人物时，除了表层欲望，还应尽量找到一个真实但未必体面的个人动机，例如省事、怕尴尬、怕浪费、想证明自己、想逃避决定、舍不得已经投入的成本。不要为了“人物有缺点”硬造缺点；只有能自然解释人物为什么会采取下一步行动时才保留。

第一人称不仅是语法视角，也要有叙述黏性。前半段优先黏在“我 / 某个具体家人、朋友、同事 / 当时发生的事”，不要刚发生一件小事就迅速跳成“现代人 / 大多数人 / 所有人”的宏观分析。需要扩大时，应先让具体事实和人物反应积累到足以支撑它。

人物的误判不能只用一句“我原本以为 A，后来发现 B”交代过去。若误判是故事发动机，应让它真实活一阵子：人物可以据此行动、合理化、嘴硬、犹豫或再试一次，直到后果让原理解越来越难维持。人物可以聪明，但不能像从答案终点倒推过程。

长期世界观建议是：
> **固定演员班底 + 半固定世界。**

可以复用人物、关系、常驻地点和道具，但不强制所有故事发生在同一地点或同一种隐喻世界。

## 8. 剧本表面应该是什么感觉

目标不是让观众感到“结构很专业”，而是：

> **像一个聪明但不端着的人，在讲一件自己真的卷进去的事。**

表面：
- 轻松口述；
- 具体人和具体事件优先；
- 有真实反应；
- 长短句自然混合；
- 允许轻微吐槽、自嘲、荒诞感；
- 抽象判断后置；
- 技术知识从故事结果里自然长出来。

抽象选题进入正文前，优先寻找一个具体人物、具体时刻或具体事件承载。一个实用检查是：把前半段的“焦虑 / 效率 / 边界 / 推荐 / 自动化”等抽象主题词暂时删掉后，故事是否仍能靠人物、动作和后果成立；如果不能，说明稿子仍过度依赖概念，需要继续落地。

“具体”不仅是写出地点和人物名，还包括现实摩擦：钱、时间、路程、工作消息、睡眠、手机、电量、饭局、家人一句话、一次付款、一个没回的消息等。抽象概念应尽量兑换成观众能想象的动作、物件和处境。

不要把“每段都要推进”误解成“每句话都必须高信息密度”。一个生活细节如果建立了人物性格、关系、现实阻力、后续梗的来源或关键情绪，它可以保留；真正应删的是既不推进故事、也不增加人物和关系理解的装饰性内容。

观众不应该明显感到：
- 三幕结构；
- 写作理论术语；
- “下面总结观点”；
- 第一、第二、第三；
- 教科书 / PPT / 演讲稿。

“景岁式轻盈”只作为表面气质参考：
- 不复制原句；
- 不复制角色；
- 不复制笑点；
- 不复制具体镜头。

结构规则应该藏在骨架里。

## 9. 开头规则

不开场自我介绍，不先讲背景百科。

优先两种开头：

### 9.1 事件 / 反常开头

直接出现：
- 异常事件；
- 意外结果；
- 奇怪决定；
- 矛盾。

### 9.2 欲望 / 冲突开头

人物可以直接说自己想做什么、讨厌什么，但冲突必须马上出现。

开头自检：
1. 第一两句里有没有具体人的处境？
2. 有没有矛盾、未知或好奇？
3. 完全不知道技术名词的人，会不会还想听下一句？

目标至少 2 项成立。

Hook 必须来自真实故事，不允许为了点击制造一个正文不兑现的问题。

---

## 10. 先让观众形成直觉，再说术语

默认顺序：

```text
具体事件
→ 第一次预期落差
→ 后果继续变化
→ 观众开始自己理解
→ 转折
→ 再说技术名 / 机制名
→ 最少量必要解释
→ 故事结果
```

不要在观众还没看懂“问题是什么”之前连续解释一堆术语。

术语不是禁用，而是：

> **只有在命名能增加理解时才出现。**

机制解释是最容易突然变成讲课的地方。

优先使用：
- 两句话的对比；
- 人物动作；
- 故事里已经出现的物件 / 状态；
- 前面建立好的比喻。

准确允许时：

> **两句对比，优先于三段定义。**

只补“故事自己还没有证明、但准确性又必须说明”的那一点。

---

## 11. 一段口播最好承担什么

有效口播主要承担六类功能之一：
- 新事件 / 新动作；
- 行动造成的后果；
- 人物反应；
- 预期被打破；
- 人物理解发生变化；
- 结局兑现。

纯解释只能作为这些东西之间的桥。

如果连续大量出现纯解释，说明故事正在变成讲解稿。

抽象信息尽量附着在：
- 一个已经发生的事件；
- 一个动作；
- 一个物件；
- 一个后果；
- 一个角色反应。

禁止：

```text
故事结束
→ 开始上课
```

---

## 12. 口语、对白与潜台词

文案必须能直接说出来。

优先：
- 一个句子一个主要意思；
- 代词对象清楚；
- 专有名词首次出现时顺手解释；
- 抽象名词不要连续堆叠；
- 长短句自然变化；
- 允许一个较长口语句由多个短意群连续推进，不把每个想法都修成独立金句；
- 自然转场优先使用“但 / 结果 / 不过 / 其实 / 而且 / 比如”等口语连接，不为了显得严谨频繁使用总结型连接词。

真实口语不等于故意结巴或堆口头禅。允许人物偶尔自我辩解、临时补一句、说到一半才把意思说准，但这些必须来自当下语义，而不是固定模仿某种说话腔。

降权表达：
- “首先 / 其次 / 最后”；
- “本质上”；
- “归根结底”；
- “真正的问题是”；
- “很多普通人的问题是”；
- “你需要的是”；
- 大段定义式排比。

### 12.1 重要台词最好是在“做事”

一句重要对白 / 旁白最好在完成某个动作，例如：
- 试探；
- 施压；
- 回避；
- 解释自己；
- 讨价还价；
- 夺回控制；
- 做决定；
- 揭示；
- 反转。

不要仅仅因为“这句话把观点说得很准确”就留下它。

### 12.2 保留潜台词

如果动作、上下文、表情或下一步选择已经能让观众看出人物感受，就不要再说：

> “我特别开心。”
> “我突然很难过。”
> “我这才意识到……”

优先：

```text
事情发生
→ 反应 / 停顿 / 动作
→ 观众自己读出来
```

### 12.3 角色要有自己的语言来源

固定的不是口头禅，而是角色看世界时自然会调用的比喻来源和词汇世界。

历史当前角色常用来源包括：
- 自动化；
- 外包；
- bug；
- 退货；
- 审批；
- 插件；
- 成本；
- 偷懒；
- 上班 / 工位。

这些不是每期必用。

配角也不应只承担“递信息 / 触发剧情”的功能。同一句意思由家人、朋友、同事、伴侣或陌生人说出时，应尽量体现关系距离、熟悉程度和各自习惯；不需要复杂人物小传，但至少要让关键台词听起来像“这个人会这么说”，而不是所有角色共用同一个 Writer 声音。

### 12.4 句子经济性

优先删掉：
- 只暴露结构的过渡句；
- 动作已经表现出来的情绪标签；
- 后面又会证明一次的总结；
- 重复的结论；
- “后来我想了想 / 接下来 / 最后我发现”式纯提纲标记。

测试：

> **如果下一句已经能让观众自己得出结论，这一句总结优先删。**

---

## 13. 动作、停顿、句尾和排版

真正的反转或转折处：
- 一个动作；
- 一次短停顿；
- 一句很短的话；

有时比另一段解释更有效。

停顿不能装饰性乱用，必须对应真实的故事状态变化。

部分反转 / 包袱可以把关键词放在句尾，让结果落下来。

剧本文本允许少量用排版表达语义节奏，例如：
- 单独一行的结果；
- 有意义的重复短句；
- 延迟出现的最后一个词。

但如果每段都强调，强调就失去意义。

---

## 14. 幽默规则

幽默来自：
- 人物反应；
- 荒诞后果；
- 人物习惯；
- 能连续运转的比喻。

不设笑点配额。

历史倾向：
- 一篇优先一个主梗；
- 最多再带一个副梗；
- 但这不是硬指标；
- 一个好梗优先沿同一语义场连续推进几句，再回到现实；后文有自然机会时可回扣一次；
- 少量持续运转的梗链，优先于每段发明一个互不相关的“聪明比喻”；
- 自嘲和自我降格优先于把别人写成笑话对象。

笑点不能：
- 引入未经核验的事实；
- 打断因果；
- 把角色写成只会吐槽的人；
- 为了“网感”强塞很快过期的梗。

“轻盈”不等于“必须搞笑”。

## 15. 两种编辑模式

内容的“业务任务”和“怎么讲”是两条不同轴。

### 15.1 故事理解型

```text
故事
→ 机制自然显现
→ 形成一个新的理解 / 判断
→ 可选的、有边界的观点
```

主要价值是让观众真正看懂。

### 15.2 故事行动型

```text
故事
→ 机制自然显现
→ 形成理解
→ 一个稳定、可迁移的判断规则 / 行动
```

不是每条都必须给方法。

方法只有同时满足以下条件才加入：
1. 直接来自这一期的核心机制；
2. 相对稳定，有依据；
3. 不需要再塞入第二个无关机制；
4. 自然解决或延伸故事中的问题；
5. 足够小，不会把视频变教程；
6. 会真正改变判断或行为。

优先方法形式：
- 一个判断规则；
- 一个分类规则；
- 一个诊断问题；
- 一个边界 / 风险规则。

否则用一个好的理解收束即可。

已删除的旧模式：
- 独立“教程型”不再作为第三种编辑模式。

### 15.3 收束仍然留在人物身上

无论理解型还是行动型，结尾优先先回答“我现在怎么看 / 我现在怎么做”，再决定是否向观众轻轻扩大。

如果人物发生了改变，不要求把问题彻底解决。一个小而具体、甚至仍有点不完美的变化，通常比完整的方法论更像真实经历；允许人物承认自己偶尔仍会犯旧毛病，并用前文已经建立的物件、动作或梗做一次自然回扣。

禁止让 narrator 在最后突然消失，只剩“你应该怎样”的建议口吻。行动型内容需要给规则时，也应让规则从人物刚刚付出的代价和新选择里长出来。

## 16. 内容任务

历史内容系统保留三种主要业务任务：
- 发现：更强调陌生人能看懂的处境、异常、好奇和推进；
- 信任：更强调机制边界和真正理解；
- 解决：题目本身天然靠近行动 / 工具 / 方法时使用。

一条内容可以有次要作用，但只选择一个主要任务。

业务任务不能破坏故事和事实：
- 不能为了转化硬塞产品；
- 不能为了“实用”强塞方法；
- 没有自然下一步时可以干净结束；
- 不强制行动号召。

## 17. Bilibili 当前编辑基线

当前历史基线：
- 主平台：Bilibili；
- 标准时长目标：3–5 分钟；
- 更长只在叙事确实需要时使用；
- 不能为了凑时长加解释；
- 日更是编辑目标，但生产吞吐能力历史上尚未被证明。

重要：
历史 70–85 秒三篇稿只用于 Writer 能力验证，不再是当前标准时长。

3–5 分钟也不是字数配额：

> **故事自然讲完优先于填满时长。**

长内容仍然必须靠：
- 新行动；
- 新后果；
- 新选择；
- 新理解；
- 新变化；

继续推进，而不是靠解释拉长。

### 17.1 锁稿前 provisional 时长预检

当尚无最终音频、且 Owner 明确允许使用 provisional SRT 进入预制作时，Part 2 在锁稿后、进入 Part 3 / Part 4 前必须按 Part 2.5 当前 provisional 规则做一次**整篇时长预检**。

- 当前 Bilibili 标准目标仍是 **3–5 分钟**；
- 该检查只用于发现“明显偏短 / 偏长”的故事结构风险，不把 3–5 分钟变成硬字数配额；
- 若明显偏离目标，优先检查是否缺少 / 多余新的行动、后果、选择、理解或变化；
- 禁止为了达到目标时长增加纯解释、重复总结、无意义停顿或机械扩写；
- 如果故事自然完整但仍偏离目标，可以保留自然长度，但必须在进入下游前显式记录该判断；
- 如果因此对锁稿做了实质修改，必须重新锁稿，并让 Part 2.5 重新生成同源 provisional SRT。

这不是正式音频时长。最终音频产生后，仍以 Part 2.5 的真实音频对齐结果为正式时间依据。

## 18. 最终输出

Part 2 最终至少需要形成：

### 18.1 机制核心
- 核心概念；
- 核心机制；
- 关键事实；
- 误解；
- 边界；
- 不确定性；
- 普通人的实际意义。

### 18.2 故事前提
- 主角；
- 欲望；
- 障碍；
- 风险 / 代价；
- 触发事件；
- 第一次行动；
- 预期落差；
- 逐步变化的困难 / 后果；
- 转折；
- 机制如何成为故事规则；
- 最终选择 / 结果；
- 去掉技术术语也能成立的故事概要。

### 18.3 最终剧本
- 内部选题题面 / 工作标题，用于追溯 Part 1，不自动作为最终发布标题；
- 开头；
- 最终锁定口播稿；
- 必要的语义节奏 / 停顿提示；
- 关键事实与台词对应关系；
- 技术术语在何时、为什么出现。

### 18.4 发布包装

剧本锁定后，再根据最终故事编译发布包装。

至少输出：
- 内部选题题面：保留 Part 1 原题，不修改；
- 发布标题候选 × 3：必须是明显不同的表达方向，不只是同义改写；
- 推荐发布标题 × 1；
- 开场 Hook：允许与标题不同，不机械重复标题；
- 封面方向：只说明核心视觉冲突，不负责具体设计。

发布标题必须：
- 来自最终剧本真实发生的事件、结果、冲突或发现；
- 不新增剧本没有的事实，不伪造现实中的亲身经历；
- 不为了点击改变机制、结论或事实边界；
- 不强制使用“为什么”；
- 优先具体事件、反常结果、判断冲突或具体发现；
- 标题、开场 Hook、封面应互相配合，但不机械重复同一信息。

Writer 不拥有最终语音时长或 SRT 时间戳。Part 2 锁稿并完成发布包装后，交给 Part 2.5 生成最终配音并完成正式 SRT 对齐。

## 19. 最终剧本检查

### 19.1 故事
- 主角有没有一个具体欲望？
- 第一次行动是不是人物自己做出来的？
- 有没有明确预期落差？
- 困难 / 后果是不是在变化，而不是重复？
- 重要段落是否真的改变故事状态？
- 有没有一个有意义的转折、选择或结果？
- 开头的问题最终有没有兑现？

### 19.2 机制
- 核心机制有没有被改写？
- 有没有新增未经支持的事实？
- 故事里的因果是否真的由机制推动？
- 技术名词是不是只在有帮助时出现？
- 机制解释有没有突然变成讲课？

### 19.3 观点
- 内部开放问题是否清楚？
- 如果有观点，相反方向是否真的被呈现？
- 观点是否由后果和选择挣出来？
- 是否过度泛化？
- 是否强行升华？

### 19.4 口语与人味
- 像人在讲事情，还是像报告？
- 具体人和事件是否多于抽象解释？
- 抽象选题是否已经落到一个具体人物 / 时刻 / 事件，而不是只给概念套人物皮？
- 主角除了“正确目标”之外，是否有能解释行动的小心思、顾虑或自我合理化？
- 第一人称是否在前半段保持足够黏性，还是很快滑成“现代人 / 大多数人”的宏观分析？
- 人物的误判是否真实影响过行动和后果，还是一句“我原本以为”就直接跳到正确答案？
- 是否存在能让观众看见生活的现实摩擦，而不是抽象标签列表？
- 是否重复解释已经演出来的东西？
- 重要台词是否在做事？
- 配角关键台词是否符合具体关系，而不是所有人共用同一种 Writer 声音？
- 情绪是否被过度直接说出来？
- 长短句和意群是否像口头叙述，而不是句句独立金句？
- 角色是否仍然像同一个人？
- 幽默是否自然？主梗是否有延展或回扣，而不是不断切换无关聪明比喻？
- 结尾是否仍能看见 narrator 本人及其具体变化，而不是突然变成建议清单？
- 有没有 PPT / 演讲腔？

### 19.5 节拍
- 每段是否新增事件、后果、信息、判断或反转？
- 有没有可以整段删除而不影响下一段的内容？
- 是否连续堆叠纯解释？

### 19.6 行动方法
- 方法是否真的来自机制？
- 是否稳定、可迁移？
- 是否为了“有用”硬加？
- 是否把结尾变成编号教程？

### 19.7 发布包装
- 发布标题是否真实兑现于最终剧本？
- 是否只是把内部 WHY 题面换几个字？
- 3 个候选是否属于真正不同的表达方向？
- 标题、开场 Hook、封面是否避免机械重复同一信息？

### 19.8 provisional 时长预检（仅适用于 Owner 授权的预制作路径）
- 是否已经按 Part 2.5 当前 provisional 规则估算整篇时长？
- 若明显偏离当前 3–5 分钟编辑目标，是否在进入 Part 3 / Part 4 前完成“保留自然长度”或“返回 Part 2 修故事推进”的明确判断？
- 若口播因此发生实质修改，是否已经重新锁稿并使 provisional SRT 与新锁稿重新同源？

## 20. 常见返回原因

出现以下情况应返回修剧本，而不是继续往分镜推进：

- Writer 改变了锁定机制 / 事实；
- 故事变成讲解稿；
- 开头过于被动；
- 比喻只是装饰，不能推动事件；
- 对白太直白，把观众已经看懂的东西又说一遍；
- 机制解释变成长篇讲课；
- 方法是后来硬接上去的；
- 观点越界或过度泛化；
- 排版 / 强调过多；
- 故事太重，像培训案例；
- 抽象题始终没有具体人物 / 事件承载；
- 第一人称很快退化成宏观群体分析；
- 人物误判只被总结，没有真正影响行动；
- 全文不断更换互不相关的聪明比喻，出现明显“AI 写段子”感；
- 结尾人物消失，只剩对观众的建议；
- 同一观点换几种说法反复重复。

## 21. 与后续模块的边界

Writer 可以标注：
- 正常；
- 加速推进；
- 包袱铺垫；
- 包袱落点；
- 反转；
- 反应；
- 收尾；
- 有意停顿。

这些只是**语义节奏意图**，不是正式时间戳。

### 下游 Part 2.5 合同

Part 2 锁稿后，必须先进入 Part 2.5：

```text
Part 2 最终锁稿
→ Part 2.5 最终配音
→ 与真实音频对齐的正式 SRT
→ Part 3 分镜
```

Part 2 交给 Part 2.5：
- 最终锁定口播稿；
- 必要语义节奏 / 停顿提示；
- 对白轮次与戏剧落点；
- 不可改动的关键事实 / 数字 / 专名。

Part 2.5 负责：
- 用最终准备采用的声音 / 语速 / 停顿生成正式音频；
- 依据真实音频完成正式 SRT 对齐；
- 输出必要停顿 / 时间信息。

正式生产不再由 Writer 或 Part 3 依赖“每秒多少字”、字符数或固定图片时长估算正式时间。

禁止：
- Writer 自己猜正式时间戳；
- Writer 用固定字速决定生产时间；
- 为了对齐方便静默改写已经锁定的剧本；
- 配音完成后日常性二次创作重写口播。

如果最终口播文本发生实质修改，应返回 Part 2 重新锁稿，再重新执行 Part 2.5 对齐。

分镜、镜头、画面视角属于 Part 3；图片执行属于 Part 4；视频装配 / 成片属于后续模块。

## 22. 核心原则

> **先锁清楚要讲懂的机制，再让一个有欲望、有小心思、也允许暂时想错的人物真正卷进问题；人物每次行动都让机制产生后果，后果逼出下一次选择，直到关键变化让观众自己看懂规则。抽象解释后置，术语在直觉形成后再出现；第一人称要黏在具体的人、事、物和现实摩擦上，角色始终是当事人而不是老师。对白和口语尽量靠动作、反应、潜台词、关系语言与生活细节推进；幽默优先从人物和事件内部长出并形成自然回扣。观点和方法都不是必需品，只有故事和机制自然挣出来时才加入；结尾仍然留在人物身上，不要求把自己写成已经彻底解决问题的人。最终剧本应该独立值得听完，同时不改变事实、不越过后续分镜与时间轴的职责。**
