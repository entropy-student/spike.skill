# Meme Music Router（热梗音乐路由器）

> 从“最近什么梗值得玩”出发，判断最适合的音乐化方式：**沿用原生热歌、借近期热歌、借经典歌曲，或直接原创一首属于这个梗的歌。**

## 它解决什么问题？

很多“热点 × 音乐”内容的问题不是没有流量，而是：

- 热点够热，但配歌很硬；
- 歌很热门，但和人物没有真正关系；
- 只剩下“这个 BGM 挺合适”；
- 为了套热歌牺牲了梗本身；
- 最终音乐听起来像 AI 随机生成，缺少记忆点。

这个 Skill 的目标是：

> **让热点负责点击，让音乐负责留人，让人物/剧情闭环制造惊喜，再让 Music Quality Radar 把作品真正做好听。**

---

## 四条路由

```text
热点 / 梗
   ↓
它本身是否自带音乐？
   ├─ 是 → Route A：保留原生音乐，寻找最绝的场景/角色
   │
   └─ 否
       ↓
近期热歌有没有天然匹配？
   ├─ 有 → Route B：近期热歌再叙事
   │
   └─ 否
       ↓
经典高认知歌曲有没有天然匹配？
   ├─ 有 → Route C：经典歌曲再叙事
   │
   └─ 否 → Route D：跳过找歌，直接原创音乐化
```

**不要为了完成“找热歌”这个步骤而硬配。**

---

## 当前最重要的创作偏好

### 1. 高能量优先

其他条件相近时：

**欢快 / 热情 / 强律动** ＞ **燃 / 爽 / 戏剧性** ＞ 中速 ＞ 慢歌 ＞ 苦情慢歌。

慢歌不是不能做，但短视频项目优先选择 3–5 秒就能产生音乐刺激的方案。

### 2. 单人物优先

默认：

> **一个热点人物 × 一个角色/场景 × 一种音乐。**

多人轮唱、四人视角不是禁止，但默认降级，因为理解成本和制作复杂度更高。

### 3. 关系闭环优先

最强创意不是“情绪像”，而是：

```text
现实人物
→ 当前热点 / 当前歌曲
→ 经典角色 / 旧身份 / 名场面
→ 歌词重新解释角色
```

固定校准样本：

> **唐艺昕 × 祺贵人 / 滴血认亲 ×「你嘴巴多毒我才不在乎」 = S。**

---

## B / A / S / S+

| 等级 | 一句话 | 用户反应 |
|---|---|---|
| **B** | 能配 | “嗯，可以这么配。” |
| **A** | 配得巧 | “这个搭配挺巧。” |
| **S** | 就应该这么配 | “卧槽，这首歌就该给 TA。” |
| **S+** | 形成新玩法 | “原来还能这么玩，我也想找一个。” |

### S 的关键测试

问一句：

> **把这首歌换成另外三首类似歌曲，这个创意还一样成立吗？**

如果换掉后最关键的巧妙关系消失，才真正接近 S。

### S+ 很严格

S+ 不是“比 S 更好听”。

它意味着：

> **这个作品让别人开始复制同一种创作结构，产生下一代作品。**

```text

    ↓

    ↓
Meme Music Router
    ↓
决定 A / B / C / D 路线
    ↓
Music Trend Radar
    ↓
仅在需要找近期热歌时参与
    ↓
Music Quality Radar
    ↓
把创意约束成真正好听的音乐方案
    ↓
Music Prompt Generator
    ↓
当前：UNVERIFIED / 待真实生成校准
```

`Music Trend Radar` 不再是每次都必须经过的固定第二步。

---

## 关于最终音乐 Prompt

当前仓库**还没有一个已经通过真实 Suno / 音乐模型生成结果校准的最终 Prompt Skill**。

所以 `Meme Music Router` 目前不会假装这一环已经成熟，而是输出标准化 `MUSIC_BRIEF`，把：

- 热点来源；
- 选择的音乐路线；
- 核心人物 POV；
- 场景；
- 叙事起承转合；
- 音乐能量；
- 必须保留 / 必须重做的元素；
- 15–30 秒传播钩子；
- Music Quality 约束；

完整交给后续 Prompt Generator。

等真实跑过多轮 Suno 结果后，再把最后一层固化成独立 Skill。
