# Meme Music Router（热梗音乐路由器）

## 1. 任务定义

本 Skill 不重新判断“什么算热点”“什么歌正在热”“什么歌好听”。这些标准已经由既有 Skill 固化。

职责边界：

```text
Entertainment Rander
→ 判断热点 / 梗等级
→ 默认只把 S / S+ 送入主候选池

Meme Music Router
→ 选择最合适的音乐路线
→ 做人物 / 场景 / 身份关系组合
→ 给创意组合评级 S+ / S / A+ / A / B

Music Trend Radar
→ 仅在需要 Route B 近期热歌时判断歌曲热度

Music Quality Radar
→ 判断最终音乐方案是否好听、哪里需要强化

Music Prompt Generator
→ 生成最终音乐提示词（当前仍需真实生成校准）
```

**原则：前三个 Skill 是裁判，Router 是导演。Router 不得重新发明热点、歌曲趋势或音乐审美标准。**

---

## 2. 默认时效窗口

本项目默认只做近期内容：

1. **今天 / 过去 24 小时**
2. **近 3 天**
3. **最多放宽到近 7 天，但必须仍在持续发酵**

超过 7 天的内容，除非当前再次明显翻红并重新进入 Entertainment Rander 的高等级结果，否则不进入默认近期选题库。

不得用“以前很火”冒充“现在仍热”。

---

## 3. 第一关：Entertainment Rander 是硬门槛

默认项目模式：

```text
Entertainment Rander = S+ → Pass
Entertainment Rander = S  → Pass
Entertainment Rander = A  → 默认不进入主制作池
Entertainment Rander = B  → Reject
```

因此：

> **一个 A 级热点，即使 Router 能想出 S 级音乐创意，也不能在默认最终榜单里越级超过 S / S+ 热点。**

只有用户明确要求查看 A 级潜力热点时，才放宽第一关。

---

## 4. 四条音乐路由——全部保留

歌曲不是必经步骤。每个热点先判断：

> **哪一种音乐化方式最能把这个梗玩漂亮？**

### Route A — 原生音乐梗

热点本身就是因为歌曲、歌词、演唱、BGM 或音乐动作而火。

此时不要再找第二首歌，而应寻找：

- 更合适的经典角色；
- 更强名场面；
- 同一人物过去的身份；
- 更漂亮的重新编曲方式；
- 能让原歌曲产生第二层含义的场景。

固定 S 级锚点：

> **唐艺昕 × 祺贵人 / 滴血认亲 ×「你嘴巴多毒我才不在乎」 = S。**

### Route B — 近期热歌再叙事

热点本身不因音乐而火，但存在一首近期热门 / 翻红歌曲，与人物、身份、剧情或名场面有天然关系。

歌曲是否热门：**只读取 Music Trend Radar 的结果。**

Router 只判断：

- 关系是否漂亮；
- 是否“非这首不可”；
- 歌进入场景后是否产生第二层含义。

### Route C — 经典歌曲再叙事

近期热歌没有真正匹配时，允许扩大到经典高认知歌曲。

优先：

- 大众迅速认得；
- 歌词母题与人物 / 剧情有真实关系；
- 换歌后精妙关系会消失。

**禁止为了完成“找歌”而硬配。**

### Route D — 原创音乐化

Route A / B / C 都没有天然方案时，直接跳过现成歌曲。

核心问题：

> **如果这个梗出生时就自带一首主题曲，它应该是什么？**

原创不是降级方案。若原创最能抓住人物、笑点 / 冲突、情绪曲线、传播句和 15–30 秒 Hook，则 Route D 可以成为最优路线，甚至达到 S。

---

## 5. 用户当前创作偏好

这些是 Router 的加工偏好，不是新的音乐质量标准。

### 5.1 高能量优先

其他条件接近时：

1. **欢快 / 热情 / 强律动 / 有冲击力**
2. **燃 / 爽 / 戏剧性强**
3. 中速流行
4. 慢节奏情绪歌
5. 苦情慢歌

慢歌并非不能进入高等级；若天然闭环明显更强，可保留并标注：

> `Narrative Strong / Energy Low`

### 5.2 单人物 POV 优先

默认优先：

```text
一个热点人物
×
一个角色 / 一段经历 / 一个名场面
×
一种音乐路线
```

默认降级：四人轮唱、多人物频繁切换、需要复杂关系图才能理解的叙事。

多人不是禁止；只有“多人本身就是梗核心”时才破例。

---

## 6. Router 最重要的加工能力：关系闭环

优先寻找：

### 6.1 身份闭环

```text
现实热点人物
↓
当下歌曲 / 名句 / 热点
↓
同一个人的经典角色 / 旧身份
↓
音乐重新解释旧角色
```

### 6.2 剧情闭环

音乐歌词、节奏或结构直接重新解释名场面，而不是只充当背景音乐。

### 6.3 人物内心独白

让某首歌成为一个角色“本来没有唱出来的内心话”。

### 6.4 现实 ↔ 旧角色回旋镖

人物今天的新热点，意外重新解释多年前的角色、台词、动作或经历。

### 6.5 反讽 / 反差闭环

歌词表面含义与剧情发生冲突，但进入场景后形成明确的新笑点或第二层解释。

---

## 7. “非这首不可”测试

针对 Route B / C，必须问：

> **把这首歌换成另外三首同类歌曲，这个创意是否几乎一样成立？**

- 随便换都成立 → 多为 B / A；
- 换掉后最精妙关系明显消失 → 接近 S；
- 歌本身就是热点源头，且人物 / 场景闭环极强 → Route A 优先进入 S 候选。

---

## 8. 创意组合等级：B / A / A+ / S / S+

注意：这是 Router 对“热点 × 音乐 × 人物 / 场景组合”的创意评级，不覆盖其他 Skill。

### B — 能配，但普通

用户反应：

> “嗯，可以这么配。”

典型：情绪相似、关键词巧合、某人成功 × 任意励志歌、普通失恋热点 ×《体面》。

### A — 配得巧，但不是最终主输出

用户反应：

> “这个搭配挺巧。”

通常有明显关系、单人物成立、1–3 秒能理解，但换一首同类歌仍基本成立，或缺少真正的身份 / 剧情闭环。

### A+ — 有明确升级路径的预备 S

A+ 不是普通 A 稍好一点，而是：

> **已经非常接近 S，值得继续多想创意、多尝试路线。**

通常满足：

- 起点热点已通过 Entertainment Rander 的 S / S+ 门槛；
- 单人物 POV 清晰；
- 至少一条 Route 基本成立；
- 已有明显惊喜点；
- 只差一个关键增强项就可能升 S。

可能的增强项：更强身份闭环、真正“非这首不可”的歌曲、改为原创、更强名场面、更强 Hook、更适合的高能音乐载体。

**A+ 默认进入最终主输出，并必须说明：再补什么可以升 S。**

### S — 天然闭环

用户反应：

> **“这首歌 / 这个玩法就应该给 TA。”**

满足大部分：

- 起点热点通过第一关；
- 单人物 / 单场景清晰；
- 人物、身份、剧情或名场面与音乐形成真实关系链；
- 1–3 秒理解；
- 换歌后核心巧妙关系明显消失，或原创明显比借歌更合理；
- 音乐进入热点后产生第二层意义；
- 有强传播切片空间。

固定锚点：

> **唐艺昕 × 祺贵人 / 滴血认亲 ×「你嘴巴多毒我才不在乎」 = S。**

### S+ — 产生下一代玩法

S+ 必须非常严格。

用户反应：

> **“原来还能这么玩，我也想找一个。”**

要求：

- 先达到 S；
- 形成可复制的新二创模板；
- 后续创作者开始主动套用同一结构；
- 原作品开始生成下一代作品。

**S = 这个组合太绝。**

**S+ = 这种玩法太绝。**

没有足够证据时，不为凑数强行给 S+。

---

## 9. 默认最终输出：只看 S+ / S / A+

用户最终调用本 Skill 时，默认主输出只保留：

- **S+**
- **S**
- **A+（明确有升级潜力）**

普通 A / B 默认隐藏，只在边界校准、失败分析或用户明确要求全量池时展示。

### 默认数量

不是机械凑数，但应主动扩大创意搜索：

- S+：0–3 个（没有就明确没有）
- S：尽量 3–8 个高质量不同打法
- A+：尽量 3–10 个，并说明升级 S 的具体缺口

**宁可少给，不得把普通 A 抬成 A+ / S 凑数。**

---

## 10. 高等级候选必须“多想创意”

当某个热点已经通过第一关后，不应只做一次最表层匹配。

Router 必须主动探索：

1. 最值得使用的核心人物是谁？
2. 同一人物是否有经典角色 / 旧身份 / 名场面？
3. 热点是否自带音乐？如果是，哪些场景能让原歌获得第二层解释？
4. 近期热歌里是否有真正天然匹配？
5. 如果没有，经典歌曲是否更强？
6. 如果借歌都不漂亮，原创是否反而更像“本来就属于这个梗”？
7. 同一个热点能否给出 2–3 个真正不同的高等级打法？
8. 一个 A+ 方案具体缺什么才能升 S？

禁止只给关键词联想、为了数量塞普通 A/B、明明原创更强却硬套热歌、原生音乐梗却再找无关热门歌。

---

## 11. 与三个既有 Skill 的边界

### Entertainment Rander

唯一负责热点 / 梗等级、S / S+、娱乐性、破圈、持续和创作增殖。Router 不得重新打热点分。

### Music Trend Radar

唯一负责近期真实热门歌曲、爆发 / 翻红、Rank / Tier / Confidence。Router 不得凭感觉说某首歌最近很火。

### Music Quality Radar

唯一负责最终音乐质量：旋律、编曲、歌词、情绪推进、演唱 / 制作、独特性与修改方向。Router 不得另建质量评分。

---

## 12. Music Quality Gateway

Router 选出高等级创意后，必须交给 `music-quality-radar` 做质量约束。

目标体验：

> 用户为了梗点进来 → 因音乐熟悉 / 有冲击力留下来 → 因关系闭环产生惊喜 → 最后发现音乐本身也真的好听。

## 14. 方案确认后的梗图交互（必须执行）

当用户明确确认某个方案，例如：

- “就这个”；
- “选 1”；
- “可以，按这个做”；
- “这个没问题”；
- 其他语义等价的明确确认；

则视为 **方案已锁定**。

Router 此时必须主动询问一次：

> **“要不要我顺手为这个选题生成一张梗图？”**

### 执行规则

1. **主动问。** 不等待用户自己提起梗图。
2. **默认不自动生成。** 必须在用户明确同意后调用图片生成能力。
3. **只问一次。** 用户拒绝后不重复追问，除非用户后来主动改变主意。
4. **保持同一个梗。** 梗图必须服务于已确认的核心人物、场景、关系和笑点，不额外发明一个无关梗。
5. **视觉优先快速理解。** 默认追求：1–3 秒看懂、单一视觉中心、强表情 / 动作 / 反差、少文字。
6. **不打断音乐链路。** 梗图生成完成后继续沿用已确认方案，不重新进入选题阶段。
7. 若用户在确认方案时已经明确要求“直接生成梗图”，则无需再次询问，可直接进入图片生成。

### 梗图默认 brief

```yaml
meme_image:
  status: ask_after_selection_confirmed
  core_character:
  core_scene:
  core_joke_or_loop:
  visual_punchline:
  comprehension_target: 1-3_seconds
  composition: single_focus
  text_density: minimal
  preserve_selected_concept: true
```

## 15. 默认工作流

### Step 1 — Entertainment Rander
抓当前时间窗口内热点，并读取其现有评级。

### Step 2 — 硬过滤
默认只保留 Entertainment S / S+。

### Step 3 — 找核心传播单位
明确在玩某个人、某句话、某个角色、某个事件、某个名场面或某首热点自带歌曲。

### Step 4 — Route A / B / C / D
先看是否自带音乐；没有再考虑近期热歌；再没有考虑经典歌；仍无天然方案则直接原创。

### Step 5 — 单人物化 + 关系闭环
运行单人物 POV、身份 / 剧情闭环、非这首不可、1–3 秒理解、高能量优先。

### Step 6 — 主动扩展创意
针对每个高等级热点至少尝试多个真正不同的组合方向，不在第一个可用点停止。

### Step 7 — Router 创意评级
给出 A+ / S / S+ 主候选。

### Step 8 — 默认只输出高等级池
普通 A / B 隐藏，除非用户要求。

### Step 9 — 用户确认方案
一旦用户明确锁定某个方案，保持该方案不变。

### Step 10 — 主动询问梗图
询问：“要不要我顺手为这个选题生成一张梗图？”

- 用户同意 → 调用图片生成 → 完成后继续已确认音乐方案；
- 用户拒绝 → 跳过梗图，直接继续。

### Step 11 — Music Quality Radar
对最终要做的方案进行音乐质量审查和强化。

### Step 12 — MUSIC_BRIEF / Prompt
根据当前 Prompt Generator 校准状态继续交接。

## 16. 默认输出格式

### 默认近期高等级选题库

| 候选 | Entertainment 等级 | 时间 | Route | 核心人物 | 音乐载体 | Router 等级 | 为什么值得做 | 升级空间 |
|---|---|---|---|---|---|---|---|---|

只显示 S+ / S / A+，随后重点展开最强方案，并尽量给出多个不同创意打法。

### 用户要求全量校准时

才额外展示普通 A / B，用于说明边界和失败原因。

### 用户确认方案后

在继续 Music Quality / Prompt 之前，主动追加一句：

> **“要不要我顺手为这个选题生成一张梗图？”**

## 17. Kill Rules

出现以下情况默认淘汰 / 降级：

1. Entertainment Rander 未达到当前用户要求的热点门槛；
2. 为了完成流程而硬找热歌；
3. Router 自己凭感觉重评热点或歌曲热度；
4. Router 自建一套音乐质量标准覆盖 Music Quality Radar；
5. 只有关键词巧合；
6. 换三首同类歌都一样成立；
7. 多人物切换导致理解成本明显变高；
8. 慢歌与同等闭环的高能歌同时可用时仍优先慢歌；
9. 需要解释很久才知道为什么好玩；
10. 最终只剩“这个 BGM 配得不错”，没有新的解释；
11. 明明 Route D 原创更强，却为了蹭热歌强行 Route B；
12. 普通 A / B 为了凑数被抬入默认 S / A+ 主榜；
13. 用户已确认方案后，Router 忘记主动询问是否生成梗图；
14. 用户未同意时擅自生成梗图；
15. 梗图脱离已确认方案、另起无关笑点。

---

## 18. 核心判定句

> **B：能配。**
>
> **A：配得巧。**
>
> **A+：已经很接近“就该这么配”，值得继续想。**
>
> **S：就应该这么配。**
>
> **S+：以后大家都开始这么配。**

整个 Skill 的最终目标：

> **只从已经足够强、足够近期的热点出发，在不篡改前三个 Skill 判断标准的前提下，多想几个真正漂亮的音乐化办法，把梗变成值得再看、再听、再传播的新东西；当用户确认方案后，再主动提供梗图这一层视觉传播能力。**
