# Meme Image Reference-First Rules（梗图参考优先规则）

本规则用于 Meme Music Router 的图片 / 梗图节点，并服从：

- `references/MEME_AMPLIFICATION_RULES.md`
- `references/LANGUAGE_FLEXIBILITY_RULES.md`

核心：

> **图片是梗的视觉放大器，不是重新选题。**

---

## 1. 先锁梗、锁名称，再生图

生图前必须已有：

- `meme_core`
- `episode_name`
- 原人物 / 原场景
- 本期选中的具体二创版本
- 最需要放大的视觉笑点

如果这些没有明确，不生成。

最终图片必须同时保留：

```text
原梗识别度
+
选中二创版本识别度
+
已锁定作品标题
```

例如：

```text
薛甄珠手撕凌玲
+
印度电影歌舞版
+
《凌玲你出来》
```

不能只剩“薛甄珠办公室剧照”，也不能只剩“印度风女人”。

---

## 2. 具体人物 / 场景先找真实参考

如果涉及真人、影视角色、综艺人物、具体物件或经典名场面：

1. 先找 2–5 张代表性参考图；
2. 提取最少量、最高识别度特征；
3. 用参考图承担身份细节，不把所有细节重复塞进 Prompt。

优先保留：脸 / 年龄气质、发型、妆容、经典服装配饰、表情动作、名场面环境与关键道具。

> **Reference first. Recognition first. Derivative fidelity second. Style last.**

---

## 3. 标题必须进入画面

标准 Meme Music Episode 的图片必须显示已锁定的 `episode_name`。

要求：

- 标题默认只出现一次；
- 标题必须清晰可读；
- 不为了设计感擅自改成另一个标题；
- 除标题外，不默认添加大量副标题、歌词或解释文字；
- 如果语言规则要求非中文或混合语言，标题可按已锁定名称直接使用。

图片的任务是让观众一眼看到：

> **这是哪个梗 + 我们这次怎么重新玩。**

---

## 4. 生图 Prompt：硬上限 200 字

最终发送给生图模型的正文：

- **硬上限 200 个中文字符左右**；
- 推荐 80–160 字；
- 不计算参考图列表、尺寸、比例等工具参数；
- 不写长篇背景故事；
- 不堆十几条 negative prompt；
- 能靠参考图表达的身份细节，不重复写。

推荐结构：

```text
主体是谁
+ 原梗场景
+ 本期二创玩法
+ 必须保留特征
+ 精确标题
+ 最重要禁止项
```

### 薛甄珠示例

> 4:3梗图。还原薛甄珠经典造型，冲进办公室找凌玲；演绎成印度电影歌舞版，动作夸张、群像惊愕、色彩高能。画面标题“凌玲你出来”。人物必须像原角色，不改成印度女性；无水印。

---

## 5. 禁止概念替身

以下默认失败：

- 具体角色 → 生成“气质相似的陌生人”；
- 经典造型 → 被更时尚的新造型覆盖；
- 名场面 → 只剩一句文字；
- 选中二创版本 → 只剩泛化风格标签；
- 已锁定标题 → 在图片节点擅自换成另一个主题；
- 为了高级感洗掉梗原本的俗、土、夸张、年代感。

---

## 6. 最终检查

生成前依次问：

1. 去掉标题，还能认出原人物 / 原场景吗？
2. 能看出本期选中的二创版本吗？
3. 标题是否就是已锁定的 `episode_name`？
4. 这张图是否让原梗更有趣，而不只是更漂亮？
5. Prompt 是否 ≤200 字？

全部通过再生成。
