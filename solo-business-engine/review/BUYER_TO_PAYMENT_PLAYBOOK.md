# 找买方 → 正当接触 → 提供可信证明 → 报价 → 实收：行动 SOP

## 0. 在任何联系前建立“准入核对卡”
`source_url / event_date / checked_at / ACTIVE? / allowed_route / platform_policy / buyer_role / purchase_scope / buyer_budget_type / eligibility / privacy_risk / owner_cash_ceiling / owner_hour_ceiling`。

- `ACTIVE` 不能从搜索引擎缓存推断；有疑义标 UNKNOWN。
- 买方未明示联系方式或平台限制接触，则不自行查私人手机号或绕平台联系；优先使用原平台提案入口。
- 发现付费委托≠已经中标/买方已经付款；支付意向、预算、录用、合同、到账分开记录。

## 1. 主动成交 SOP（公开委托 / 合规企业业务联系）
1. 选择一种明确 Buyer/Trigger/结果，保存原始请求和限定条件。不要将“服务已存在”当能力证明。
2. 合规核对：地区与平台规则、是否允许与该买家接触、个人资格、投标费用、截止日和已有人选状态。
3. 不超过一页的定制说明：复述买家提出的事实性任务、明确 1–2 个能验证的风险点、展示自制 DEMO（标注虚构数据）、提出 1 个能回答的澄清问题。
4. 取得回复后确认：能批准付款的人是谁？具体采购条件与截止？现有替代/预算？必须得到哪个结果才验收？
5. 先核对本人在固定范围内可以兑现，再提交带价报价。提供小范围试点是缩范围，不是必然降价。
6. 对方明确接受后，按平台正式建立合同或订单、确认押金/里程碑、权限、素材使用、隐私、期限、修订、退款。
7. 记录 **付款事件** 与退款、交付验收、工时和意外事件。只有实际收到/正式平台交易可验证，才算本人的 Transaction。
8. 被拒绝/退订/沉默，不绕平台追踪或群发；沉默记未知，不等于无需求。

## 2. 被动承接 SOP（搜索意图 / 交易平台）
1. 搜索 `[具体结果]+服务/报价/代做/模板/替代品`，区分购买型与资讯型，不假设点击等于购买。
2. 只做 1 个有实用信息的样例页或平台服务页：买家是谁、成果截图/演示、交付范围、限制、真实报价或清晰询价方式、验收、退款与联系方式。
3. 设来源可追踪参数（可在合规前提下匿名聚合），区分 `visit / qualified_inquiry / quote / paid`。
4. 早期流量不足输出 `INCONCLUSIVE`，不要用内容浏览量宣称市场成立。若存在合规小预算广告，必须在 Owner 给出风险上限后才申请执行。
5. 依据真实查询调整页面，不量产低价值 SEO 文本；广告来源与自然访问分别记录。

## 3. 合作/转介绍 SOP
寻找已经长期服务同类买家的上游渠道，而不是买个人联系人名单；公开说明给伙伴新增的结果、可交付样例、责任和佣金。第一轮只做一位合作伙伴的小试点，登记独立新增买家与利润分成；客户数据必须有合法共享依据。

## 4. 一笔交易的“真实性事件”
`PUBLIC_LISTING → CONTACT_PERMITTED → CONTACT_ATTEMPTED → REPLIED → BUYER_QUALIFIED → SCOPED → QUOTED → BUYER_ACCEPTED → CONTRACTED → FUNDS_CONFIRMED → DELIVERED → ACCEPTED → REFUNDED/REPEATED`。
可跳级进入交易，但必须有真实证据；不同订单及退款、争议分账；未到账、不提供支付通道或平台不让转移时 `BLOCKED_BY_REAL_INPUT`。

## 5. 两套价格与范围的操作原则
- `Price > Floor?`：实际现金交付、平台支付、一次性申请成本、退款准备、个人时间都纳入压力测试；至少知道下行亏损暴露。
- `Buyer willing?`：只认真实选择和交易，不从“愿意买”问卷推销售。对方拒绝先核对 Proof/Trust/Timing/Authority/Alternatives，再考虑改 Price。
- `Deliverability`：无法兑现不得收定金；可先做假数据 Demo 和技术证明，或先取得非经济性设计伙伴承诺。

## 6. 失败归因矩阵（不能跨级下结论）
| 观察 | 当前最大未知 | 唯一合适的下一实验 |
|---|---|---|
| 搜到多条项目却没有资格投 | Access | 换有进入资格的项目/渠道，核查账号权限 |
| 可投但客户没回复 | Relevance / Competition / Timing | 核对提案和证明、岗位是否仍活跃，不得断言没需求 |
| 回复多却无预算或采购权 | Buyer Role | 调整到有授权的负责人/采购人 |
| 有报价请求无购买 | Offer / Trust / Proof / Timing | 向明确客户核对拒绝原因，不立刻打折 |
| 付费后交付超时 | Deliverability / Economics | 暂停扩单并先补救退款/交付 |
| 当前价格有订单但亏钱 | Unit Economics | 缩小交付范围/测试可持续价或停止 |
| 重复订单主要来自熟人 | Channel independence | 增加一条独立购买入口并记录来源 |
