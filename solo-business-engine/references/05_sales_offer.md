# 05｜从陌生人到实际付款：报价、证明和拒绝诊断

## 提问顺序（不是死板话术）
1. 你上次在[具体任务]遇到的情况如何？发生时间？
2. 当时如何处理？谁负责？用什么系统/人力？
3. 如果不处理，具体会损失什么或错过什么？如果是礼物/情感产品，问准备送给谁、何时、当前购买替代。
4. 过去尝试了什么？为什么继续/放弃？已付出成本是否可证实？
5. 谁能批准试用或订单、谁实际付款？什么时候必须拿到结果？
6. 在不涉及隐私/高风险承诺前提下，给出真实有界样例，确认是否解决关键任务。
7. 提供明确范围和带价方案，让对方选择**现在购买/提出条件/拒绝**。

## 三种按购买场景的 Offer
- `Paid Pilot`：高客单复杂 B2B。先定有限任务、里程碑、成功定义、保密/数据责任、付款节点。
- `Productized Service`：个人/企业明确委托。定义固定输入、交付物、修订次数、交期、适用范围/退款。
- `Small Purchase/Pre-order`：礼品、体验、实物。展示真实样品/预览，告知实际交付日期、量产能力、退款，**不可假装有库存或已发货**。

## Offer 合同结构（必须填）
`谁买 / 什么事件触发 / 最终得到的结果 / 不包括什么 / 客户提供的输入 / 交付物格式 / 交期 / 验收方法 / 价税运费 / 支付节点 / 取消与退款 / 隐私/权利 / 下一步CTA`。

## 价格纪律
观察竞品价格、替代成本和客户价值，但**不把其等同于本人的 WTP**。必须同时检查最低可持续价格（真实边际成本+售后+平台费+人工时耗）及客户支付路径。不同套餐可以按 Scope/Speed/Customization/Continuity 分层；价格试验不要把目标客户、样例和购买路径一起改变。

## 分析拒绝的分类
`NO_BUDGET / NO_AUTHORITY / NO_URGENCY / NO_PROOF / NO_TRUST / NO_FIT / ALTERNATIVE_GOOD_ENOUGH / TOO_MUCH_FRICTION / PRICE_VALUE_GAP / PROCUREMENT_BLOCK / NO_RESPONSE_UNKNOWN`。
对方仅说“贵”时，不自动下调价格；先辨识购买对象是个人/企业、预算审批是否已到位，以及缺的是结果证明、范围、时机还是付款方式。

## 何时免费
仅当小范围可完整交付、能学习购买行为、成本受控，且免费不会吸引与真正购买人不同的群体时使用。免费不验证商业成交；正式入账记 `PAID_NET`, 试用记 `SAMPLE_DELIVERED`，退款冲减。

## 示例开场（需逐人依据真实事实定制，且合规）
**采购委托响应**：看到你发布的 [具体交付目标] 和 [截止期限]。我可以在 [输入/边界] 下提供 [可核实样例]，计划分 [两项里程碑] 完成。预算范围是否包含 [具体交付项]？我会按平台流程提交正式报价。

**公开业务联系**：在贵公司的 [公开真实流程/事件] 中注意到 [可核实事实]。我最近在验证一种 [具体结果] 的服务，初步演示 [真实功能与边界]。是否由你负责这项工作，或应该联系相关采购负责人？若不需要，我不会再就此联系。

**报价**：按刚才确认的范围，我能交付 [清晰成果]，需要你提供 [合规输入]，在 [时间] 前完成。价格 [货币与数额]，包括 [内容]，不包含 [边界]。验收按 [规则]，不能交付时按 [退款条款] 处理。若需要，可以在 [支付渠道] 正式下单。

## 拒绝后怎么用证据，而不是骚扰
最多按对方明确允许的方式进行合理跟进；如果拒绝/退订，立即停止。记录实际原因和所在阶段，提取机会层面的学习，禁止把个人身份信息加入公开训练素材或永久报告。
