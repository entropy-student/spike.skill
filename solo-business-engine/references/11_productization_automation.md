# 11｜产品化与自动化：先定义稳定价值，再减少每单人工

## 反误区
- **产品化 ≠ 开发 SaaS**：可体现为固定交付规格、模块化设计、批量生成模板、许可、训练、可复制 SOP、合作分工，最终才可能是软件。
- **自动化 ≠ 自然赚钱**：代码维护、集成失效、API成本、客户支持、退款、错误处理可能比原人工贵。
- **标准化 ≠ 剥夺个性化**：把可重复核心与允许定制的边界分开；某些高端服务/礼品的定制恰是付费理由。

## 机会进入前的产品化诊断卡
1. 用户买的是哪种不变结果？它可以用 1 句可验收标准描述吗？
2. 入参有哪些（数量、格式、隐私、权限），前后处理是否稳定？
3. 交付流程拆成 `共同核心步骤` 与 `定制/异常步骤`；每步耗时/失败率 `UNKNOWN` 时测小样。
4. 多样客户的输入变化会带来怎样的增量小时和支持？有不可预见的专家判断吗？
5. 哪些部分可由模板、流程或软件复用，是否有安全和人工确认边界？
6. 自动化预计节省的是谁的时间？维护/审计/客服会增加多少？
7. 若月/年收入增长，Owner 工时能否趋于低增长，或必须等比例扩张？
8. 若自动化失败，能否安全降级为人工/撤销并履约？

## 五级复用选择（不同模型可停在任意级）
- R0 `探索性一次交付`：有经济价值，但尚无重复证据。
- R1 `规格化 Offer`：固定输入、范围、验收、修改次数、报价。
- R2 `可复用模块`：样式、脚本、标准操作、组件、问答和质检。
- R3 `流程与工具自动化`：预检、构建、渲染、报告与支付/交付；维护和人工复查被计入。
- R4 `可持续自助交付`：用户可独立购买/获得结果/售后，异常有处理路径；需真实线上验证。
不要将 R4 规定为所有商业类型的必达目标，合格的高毛利精品服务可能止于 R2。

## 小型自动化实验合同
```
真实重复输入样本: [至少跨不同条件，数量为计划而非统一规则]
原人工流程 / 各步工时: [观察值/UNKNOWN]
自动流程 + 异常机制: [可运行 Demo]
对照指标: 端到端 Owner 总小时 / 每个合格交付，退款投诉与返工
成本: 研发/算力/接口/部署/维护/安全/支持
可逆性: 故障时如何恢复、保住承诺
收益假设: [估计且可推翻]
决策: KEEP / ITERATE / HOLD / REJECT
```
“自动化成功”必须包括**完整履约的真实成本**，不是脚本执行时间很快。
