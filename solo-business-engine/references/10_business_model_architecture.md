# 10｜商业模式架构：先判断该不该经营，才决定怎么获客

## 使命与六层合同
一个方向不能只用“有人抱怨”和“存在竞品价格”表示可做。每个候选列出：
1. **购买机制**：谁付款、受益人是否同一人、触发时点、需求频率、当前预算/替代开支。
2. **价值创造**：实物/数字结果/节省时间/避免损失/体验/身份/礼物；证据是实际行为，非口头兴趣。
3. **价值捕获**：收一次、项目、标准化套餐、许可/数字品、按次、订阅、使用量、代理/交易佣金；为什么该结构匹配交付频率。
4. **交付结构**：标准核心、个性差异、输入边界、例外、验收、安全、交付现金成本与返工。
5. **获客结构**：交易平台/搜索/主动接触/内容/合作/推荐；购买状态、许可、对单平台依赖、需投入的 Founder 小时。
6. **可持续性**：实际贡献、资金周转、个人总时耗、季节性、支持/退款风险、可复用资产。

## 候选商业模型路由（不是排名）
| 类型 | 何时成立候选 | 早期验证 | 典型陷阱 |
|---|---|---|---|
| 一次性标准数字商品 / 模板 / 许可 | 买家买明确文件或工具，交付可复制 | 真实样品 + 明码标价 + 付款 | 版权、分发完全靠平台 |
| 个性化但模块化产品 | 用户支付个性化溢价，但制作有稳定结构 | 3种不同输入的样片+实际工时测量 | 个性输入导致不可控返工 |
| 标准化服务 | 可定义范围/交期/验收且可用复用流程交付 | 一个带价限定试点，完整工时追踪 | 把无限服务承诺包装成套餐 |
| 独立顾问/高价值项目 | 每单高价值、用户信任专家判断 | 买家愿意为独特判断付费，且净利润/小时成立 | 创始人被永久锁在交付中 |
| SaaS/订阅/监控 | 客户实际**持续**得到新价值并按周期使用 | 多个周期使用/续费/取消与支持成本 | 月费而无持续价值，流失和维护高 |
| 使用量/按次计费 | 价值/资源成本随使用事件发生 | 能量化有效消费事件和计费准确性 | 高峰算力成本、支付小额费率 |
| 交易撮合/代理/联盟 | 实际供需交易和归因可验证 | 可追溯有效成交与合规分成 | 单方依赖、平台规则、信任双边冷启动 |
| 实物 / 礼物 / 体验 | 有明确时点或情境的真实消费 | 样品、预售规则、交期、退换与履约验证 | 库存、物流、季节性、满意度 |
| 内容/受众驱动 | 反复触达目标人群且可辨认购买旅程 | 相关内容 → 合格咨询 → 真实支付 | 有观看无购买、持续制作成本 |

## 预审 Gate（用来决定下一实验，不能自动推断全市场效用）
| 门槛 | 必答 | 常见输出 |
|---|---|---|
| BUYER & TRIGGER | 为什么现在、谁能支付 | UNKNOWN → 先见买家 |
| WINNABILITY | 与竞品比，具体给买家什么变化 | UNKNOWN → 做真实证明/换细分 |
| UNIT CONTRIBUTION | 是否能在可信价格覆盖可变成本和获客成本 | UNKNOWN → 计算范围/测成本 |
| REPEATABLE DELIVERY | 稳定部分、差异部分、异常频率能否界定 | UNKNOWN → 小样测时，不以口号判断 |
| REPEATABLE DISTRIBUTION | 哪条渠道能不断获得独立买家 | UNKNOWN → 对照获客机制 |
| OWNER & DOWNRISK | 失去多少现金/精力，能否接受退货和负面结果 | 不可承受 → HOLD / REJECT |

**结论**：`MODEL_FIT = TEST / HOLD / REJECT / INCONCLUSIVE`。如果缺少重要数字不得硬评分。要求同时注明**最有吸引力的替代模型**及其反证，不能看到订阅就一律升级 SaaS。

## 与“第一单”的关系
首笔实收可证明某 Offer 一次成立，不证明可复制；并非为了未来软件化而强制接低价外包单。允许先卖服务、先做真实 Demo、小批预售或直接发布模板——以经济性、履约和客户信任条件作选择。
