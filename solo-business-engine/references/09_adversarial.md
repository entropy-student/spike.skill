# 09｜对抗性检查：核心盲点与失败后的可诊断解释

| 如果出现 | 不能下结论 | 最小修正/验证 |
|---|---|---|
| 100 个抱怨者都没回 | 市场无需求 | 看是否触达合法/可达、对象是否采购人、渠道是否匹配 |
| 只有竞品成功案例 | 我们也能卖 | 查差异化、买家切换与渠道进入成本 |
| 只是平台上的预算 | 已经成交 | 正式响应，并区分采购意图与采购决定 |
| 熟人买了3单 | 可重复获客 | 从独立不相关的买家与来源重现 |
| 免费体验 500 人 | 商业证实 | 先出现真实带价采购行为 |
| 用户说太贵 | 降价准有效 | 测是信任、需求范围、预算权、替代更好还是购买时机 |
| 情感产品没有高频痛点 | 应该淘汰 | 看礼品场景/身份/审美、带价订单与季节 |
| 很多进来但不转化 | 扩大流量 | 漏斗区分不需要/不信任/支付摩擦 |
| 订阅第一月收入不错 | 留存成立 | 看续费周期、取消、退款和维护负担 |
| 高营收但交付耗时巨大 | 自动化后一定会好 | 人工时间账、异常/支持成本、可逆自动化试验 |
| 需求需要敏感账号凭证 | 给个脚本就能测试 | 客户安全授权与合法技术路径先验 |
| 一次性节日礼品没复购 | 不可能长期做 | 是否有稳定新增人群、季节性、介绍和客单贡献 |
| 广告高点击无订单 | 广告优化成功 | 买家意图、落地页、完整付款归因与成本 |
| 低价试点订单很多 | 正常价格也卖得动 | 单独测试可持续价位，限制客户群差异 |
| 研究文献 40 篇 | 系统已验证赚钱 | 必须有真实新客户/收款/交付/经济性 |

## 对原 Skill 不可盲信的假设
“每次只改一个变量”适用于需归因的实验，不适用于完全未知市场的探索性宽扫描；“免费价值→付费扩张”不是所有品类必需；“单一主瓶颈”在机会组合阶段不应伪造；“Transaction”尚不足以证明履约与满意。详见 `METHOD_COMPARISON.md`。
