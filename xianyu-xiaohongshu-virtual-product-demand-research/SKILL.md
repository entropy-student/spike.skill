# 闲鱼 / 小红书虚拟商品需求研究 v2.2

目标：发现平台上值得关注的具体商品与购买问题，分清**观察到什么、支持什么结论、下一步需要验证什么**。默认交付可复核的市场目录，不承诺市场全集、销量预测或盈利。

## 1. 路由与范围

从当前请求确定平台、商品范围、研究时间窗、模式和工作预算，写在底稿开头。已有约束直接复用；只有缺失信息会改变结果时才提问。未指定时间窗，使用最近 90 天，并明示这个假设；未指定预算，采用一轮有限研究并声明本轮搜索/访问预算。

- `MARKET_MAP` 默认：发现、复核、刷新市场，或问哪个值得继续研究。
- `TEST`：用户要求卖什么、实际测试什么、优先投入什么。先完成必要需求判断，再读 [Test Mode](references/OPTIONAL_TEST_MODE.md)。仅提供实验方案不等于授权发布、收款或联系他人。

双平台分别判断。虚拟商品可含会员、权益、数字文件、工具及标准化服务；不要擅自将范围缩成“自己会制作的文件”。风险影响执行，不删除真实市场观察。

## 2. 发现与重复调用

从平台商品/Offer 与买方问题两个方向发现；官方类目、第一方数据、相关推荐、求购、评论、问题搜索都是入口。类目树与推荐列表都不代表市场全集。能力相邻、服务产品化可以补充候选，必须注明推导。

闲鱼重点看直接商品的实际规格、价格结构、想要/浏览、询价/求购和可归属成交。小红书重点区分内容学习、免费索取与针对付费商品的求购、询盘、商品动作。不能将一个平台的证据移给另一个平台。

使用 [证据规则](references/EVIDENCE_RULES.md) 与 [研究底稿](templates/RESEARCH_LEDGER_TEMPLATE.md)，边观察边记录，避免事后凭印象补来源。先宽覆盖再补高价值候选，不要求固定数量或冠军。

重复调用复用旧候选与来源，刷新过期关键证据、会改变结论的未知项及高价值未覆盖区域；同时安排一个小规模的**旧候选之外**探索入口，避免目录固化。单一 SKU 的定向复核不必重扫全市场。稳定原始事实可复用，动态数值与规则不能默认仍有效。

停止依据与覆盖范围一起交付：

- 本轮范围内，实质不同的入口已没有新增重要候选或改变判断的证据，可写“本轮局部饱和”；不能外推全市场。
- 达到时间/访问/现金预算，或继续补证的收益低于成本，可以停止并列出剩余缺口及下一步。未知项无需全部消除。
- 访问受限时记录 `PARTIAL/BLOCKED`，必要时尝试一个可用渠道，不能无限重试，也不能把无法访问解释为没有需求。

市场面标 `SCANNED/PARTIAL/BLOCKED/EXCLUDED`，记录查询/入口、样本规模、限制与排除理由。输出“完成本轮”与“覆盖充分”是不同判断。

## 3. 证据归属：对象、时间、来源

每条证据记录来源定位、原始事实、信号数值、观察日、**行为/统计期间**、支持的具名对象、Scope、来源性质、Lineage 和访问限制。时期未知就写 UNKNOWN；今天打开网页不能刷新过去的成交期间。

Scope 使用 `FAMILY/PRODUCT_TYPE/SKU/BUNDLE`，同时写出具名对象。枚举相同不等于对象相同。广泛“摄影预设”不能确认每一种日系预设；AI 教程成交不能确认附加项目文件/Workflow 的组合。向更宽范围汇总只能表明其中存在需求，不能声称整个范围普遍成立。

直接成交证据若对应完整 Bundle，可确认这个 Bundle，无需分别证明各部件；各部件单独成交也不能反向证明组合有人买。相邻推导标 `DERIVED_ADJACENT`，不继承需求等级。

按本轮时间窗记录 `CURRENT/HISTORICAL/UNKNOWN`。累计计数无起止时间时为 UNKNOWN，不证明近期增长；历史证据保留其原等级及期间，但不能计入“当前已确认”。

来源性质与强度分开：直接平台记录、第一方平台数据、媒体转述、卖家自述、推导。媒体明确转述平台交易数据可支持 reported D4，必须保留原始归属、期间和统计口径；卖家无证明的“已售 X”是 CLAIM，不自动成为交易。卖家全店累计销量不得作为单 SKU 销量。

## 4. Demand Level

先判断信号含义，再判断复现；弱信号重复仍是弱信号。

| Level | 要求 |
|---|---|
| D4 | 可定位、可归属到具名对象的付款/成交记录，或直接支持该对象的第一方平台交易数据（转述须标 reported） |
| D3 | 多个独立买方/行为针对同一对象的**明确付费购买意图**：如围绕付费 Offer 的价格、交付、购买条件询盘，明确有偿求购或订单承诺；尚非付款 |
| D2 | 一个明确购买意图，或一个/多个想要、收藏、搜索、浏览、点赞、泛问教程/求资料等弱兴趣信号 |
| D1 | 仅观察到平台上可归属的供给、类目或商品存在；内部原型/交付演练不是平台供给证据 |
| U | 无法归属或无可用证据 |

“想要”即使出现在很多卖家、数值很大，也不能单独触发 D3。D2 仍可有很高的研究价值。免费索取和学习兴趣不能当付费意图。

独立性按 underlying 买方/行为判断，不按页面数量。不同卖家未必独立；同一卖家的多个独立买方可以支持 D3。镜像、同一推荐卡重复出现、卖家矩阵、重复转载或同一事件只能算一次。独立性未建立时不能用复现升级。

`CONFIRMED_DEMAND = D4`，`PROBABLE_DEMAND = D3`，`WATCHLIST = D2/D1/U`。这些只描述存在性证据，不证明需求规模、代表性、转化率或利润。历史/时期未知结果与当前结果分开汇总。

Confidence 仅描述结论的可复核程度：HIGH（来源、归属、期间及 Lineage 清楚），MEDIUM（有重要限制但事实可定位），LOW（访问不完整、来源链/归属不清或主要为推导）。不靠降低 Confidence 保留本来不成立的 D3/D4；反证破坏归属、时间或独立性时直接修正等级或当前状态。

## 5. 风险与执行

Risk 单列 `NO_FLAG_OBSERVED/REVIEW_REQUIRED/HIGH_RISK/UNKNOWN`。未查就是 UNKNOWN；NO_FLAG_OBSERVED 只是本轮检查没有发现明显问题，不是授权或法律保证。需要判断是否可执行时，核对当前官方规则、资格、权利和交易路径。

强需求可以伴随高风险。找不到货源也不等于没有需求。低价引流、免费替代、热点短峰、推荐偏差、退款与交付争议是反证/限制，按它们实际影响的结论记录。

用户只要短答时可缩短展示，仍须保留可回看的底稿。报告本轮覆盖、停止理由和继承/新观察的区别。不把榜单长度或标签数量当成功标准，不将 WATCHLIST 写成“没有市场”。
