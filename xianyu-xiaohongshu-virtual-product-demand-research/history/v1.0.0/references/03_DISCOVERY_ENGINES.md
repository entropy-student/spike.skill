# Discovery Engines

Discovery 目标是高召回，不是证明。

## 覆盖要求
无垂直约束：30–50 raw ideas → 去重为 15–25 Candidate Units；至少 6 个 Problem/Desire Cluster、5 种 Product Form；双平台任务必须覆盖两端。

## 八个引擎
1. Search-intent-first：关键词/长尾问题 → 高意图场景 → 产品假设。
2. Problem/Question-first：求助、抱怨、反复提问 → workaround → 失败成本。
3. Transaction-structure-first：同类长期卖家/价格带/产品结构 → 支付方向 → 缺口。
4. Review/Dispute-gap-first：差评、退款、投诉、售后 → Must Keep / Must Fix。
5. Service-to-Productization：人工服务 → 重复交付 → 标准化/自动化产品。
6. Content-to-Offer：高频内容主题 → 用户下一步任务 → 可执行交付物。
7. Workflow/Template-gap：重复整理/填写/分析/生成 → 模板/工具/自动化。
8. Capability/Adjacency-first：本次明确能力 → 相邻需求；只能生成候选，不能证明市场。

## 搜索纪律
- 闲鱼：优先 exact query、价格带、卖家结构、商品描述、购买语言；
- 小红书：优先搜索词、笔记问题、评论中的下一步需求、内容主题、商品/服务路径；
- 任何热度信号都要回到 Problem + Payment + Platform Fit 二次验证。

若跳过某引擎，必须记录 skip reason。
