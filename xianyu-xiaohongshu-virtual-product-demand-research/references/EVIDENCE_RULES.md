# Evidence Rules

## 信号强度

~~~text
真实订单 / 平台交易数据
> 明确购买动作 / 有效询盘
> 搜索 / 想要 / 收藏
> 浏览 / 点赞 / 曝光
~~~

不同信号不能混写成“销量”。

## Provenance

| Label | 含义 |
|---|---|
| PLATFORM_TRANSACTION | 平台/第一方交易数据直接点名商品族 |
| PLATFORM_CATEGORY | 官方类目证明市场面存在 |
| DIRECT_SKU | 当前直接商品/Offer |
| RELATED_RESULTS_CLUSTER | 多个相关/推荐结果形成商品簇 |
| DERIVED_ADJACENT | 从相邻需求推导 |

## Demand Level

| Level | 标准 |
|---|---|
| D4 | 第一方商品族交易证据或可明确归属 SKU 的成交证据 |
| D3 | 多个独立当前商品/卖家重复证明 |
| D2 | 一个直接 SKU 或一致商品簇 |
| D1 | 类目/宏观/相邻推导 |
| U | 不足 |

高“想要”只能增强证据，不能自动升级独立性。

## Signal Lineage

重点检查：
- 同一卖家多个商品；
- 同一商品被推荐到多个页面；
- 同一热点/新闻造成多处曝光；
- 同一数据源被多个文章复述。

同源只能算一条底层信号。

## 平台差异

**闲鱼**：更看重当前直接商品、平台内购买结构、搜索式标题、价格和多卖家重复出现。

**小红书**：更看重重复搜索问题、商品/店铺动作、明确求购/合格私信，以及多个独立账号是否持续围绕同一需求出现。点赞收藏只算 Attention。

## Counterevidence

至少检查：
- 单一爆款/单一卖家；
- 低价引流；
- 热点短峰；
- 推荐机制而非真实搜索；
- 相邻需求误投射；
- 免费替代。

Market Map 中反方证据用于降低置信度，不覆盖已经观察到的需求事实。
