# Value Architecture

用 `CREATE → DELIVER → CAPTURE` 解释产品，而不是只列功能。

## CREATE
- 谁提供关键输入？
- 哪个活动/机制把输入变成更有价值的结果？
- 产品减少了什么摩擦：时间、成本、搜索、复杂度、协调、信任、风险、认知负担、体验？

## DELIVER
- 用户如何发现、购买/访问、收到并实际使用价值？
- 有哪些渠道、履约、软件基础设施、服务人员或生态参与者？

## CAPTURE
- 谁愿意为哪一段价值付款？
- 企业/卖家通过价格、订阅、抽成、耗材、授权、广告、服务等拿走多少价值？
- 哪些合作方/供应商/平台也会对价值池提出索取？

Value creation 不等于 value capture。一个产品可能创造巨大价值，但因为竞争、供应商、版权方或平台议价而只保留很少部分。
