# Frame Blueprint — Candidate v0.1

## Boundary

G4 decides what the image means.

Frame Blueprint decides how visual attention is arranged.

Asset Compiler later binds references and execution mode.

## Every Blueprint locks

- dramatic_job
- frame_archetype
- focus_mode
- primary_focus
- optional secondary_focus
- attention_entry
- attention_exit
- transition_mode
- composition_mode
- density
- visual_intensity
- background_anchors
- remove_or_suppress
- text_policy
- brand_mode
- ui_mode
- continuity_preserve
- frame_delta
- withheld_information
- acceptance_criteria

## Focus modes

### SINGLE
One dominant focus.

### DUAL
Two intentionally related focuses.

### FIELD
Multiple elements form one coherent state/pattern.

Do not use FIELD merely to fit more content.

## Frame archetypes

- CHARACTER_REACTION
- CHARACTER_ACTION
- RELATIONAL_TWO_SUBJECT
- OBJECT_EVIDENCE_INSERT
- WORLD_STATE
- DUAL_COMPARE
- MATCHED_SETUP_REVEAL

## Attention path

Each frame should define:
- entry
- primary focus
- exit/handoff

Transition modes:
- HOLD
- HANDOFF
- RESET
- WITHHOLD_REVEAL
- INTENTIONAL_BREAK

## Density

Use:
- LOW
- MEDIUM
- HIGH_JUSTIFIED

High density needs a narrative reason.

## One-main-delta

For continuity/derive frames, change only what the story state requires.

## Text

Exact critical text defaults to POST_OVERLAY.

Image generation owns visual shell/layout.
Post overlay owns exact verified wording.

## Brand

Default:
`NONE`

Use real brand only when causally required and verified.

## Withhold/reveal

A setup frame must not leak the payoff object/state.

## Acceptance

A Blueprint must preserve:
- G4 meaning
- P1 discoverability
- POV
- reveal logic
- subtitle-safe composition
- no unnecessary explanatory clutter
