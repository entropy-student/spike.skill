# SRT Timing

SRT 是 Script Lock 之后的派生交付物。它只能切分已经确认的 `Best Hook + Body Continuation` 并生成时间码，不得为了字幕重新改写、删减或补充口播正文。

## Timing source priority

生成 SRT 必须沿用口播稿的同一套语速来源：

1. 真实音频 / 真人实测对齐结果；
2. 用户明确指定的 `speaking_rate_cps`；
3. 中文未指定时默认 `4.8 个可朗读字符/秒`；
4. 其他语言或无法合理换算时只能标记为 `ESTIMATED`。

不得出现“口播稿按 4.8 字/秒规划，但 SRT 又按另一套固定速度生成”的情况。

## Core formula

没有真实音频时，每个字幕块的估算时长按：

`segment_duration_seconds = segment_spoken_chars / speaking_rate_cps`

其中 `segment_spoken_chars` 沿用 Timing Contract 的计数逻辑：中文汉字按一个可朗读字符计；标点、Markdown、空白不计；数字、英文缩写和英文单词按实际朗读占用近似换算。

整条 SRT 的累计结束时间应与 `Hook + Body Continuation` 的预计口播时长基本一致。允许因毫秒取整产生极小误差，不允许人为压缩时间轴来“塞进”目标时长。

## Segmentation

先按语义和自然呼吸切分，再按语速计算每段时间。优先满足：

- 一个字幕块表达一个完整的小意思或自然呼吸单位；
- 不在专有名词、数字单位、固定短语中间硬切；
- 单段过长时按语义拆分，单段过短时与相邻句合并；
- 默认尽量控制在约 1.5–4 秒一块；必要时可超出，但不能通过篡改语速或文字解决；
- 每个块通常 1–2 行，具体换行服务可读性，不改变时间计算；
- Hook 仍然只出现一次，SRT 从 Hook 第一字开始进入时间轴，然后连续进入正文续接。

## Timestamp rules

- 第一段从 `00:00:00,000` 开始；
- 时间码连续递增，不重叠、不倒退；
- 默认相邻字幕块首尾连续，不人为插入静音空隙；
- 使用标准 `HH:MM:SS,mmm --> HH:MM:SS,mmm`；
- 序号从 1 连续递增；
- 输出必须是 UTF-8 `.srt` 文本。

## Real audio override

如果已经存在真实录音、TTS 或精确字词级时间戳，字符语速模型只作为先验，不再作为最终时间轴。此时应使用真实音频对齐结果，并将输出状态标记为 `MEASURED/ALIGNED`。

## QA

生成后必须检查：

- SRT 文本与正式口播逐字稿逐字一致，不漏句、不重复句；
- Hook 没有因为“单独展示”而在 SRT 中出现两遍；
- 使用的 `speaking_rate_cps` 与口播稿一致；
- 时间码无重叠、无倒序；
- 最后一段结束时间与预计总口播时长合理一致；
- 若用户之后提供真实音频，应重新对齐，而不是继续沿用估算时间码。
