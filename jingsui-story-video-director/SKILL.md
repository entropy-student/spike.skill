# 0. 目标

把一个主题转成一条单人可持续生产的“故事型漫画口播视频”。

默认链路：

主题 → 切口 → 口播稿 → SRT → 视觉语义拍 → Scene/IP Bible → 生图 Prompt → 剪辑计划 → QA

核心不是“先讲一个道理再找例子”，而是：

> 一个具体的人遇到一件具体的事 → 事件继续发生 → narrator不断吐槽/自嘲/联想 → 中后段才把故事提炼成一个更普遍的判断。

# 1. 已校准样本

## AUDIO
三条用户提供真实旁白：
- 约 222.1s / 1256 中文字 / 5.66 字每秒
- 约 243.4s / 1539 中文字 / 6.32 字每秒
- 约 161.2s / 914 中文字 / 5.67 字每秒
- 加权平均约 5.92 字每秒

默认脚本速度：5.7–6.2 中文字/秒；默认 5.9。

## VIDEO
已加入三条完整 1920×1080、约30fps MP4，总时长约 564.1s。

多样本视觉工程中心值：
- visual beat 中位数约 2.7s；
- P25 中心约 1.8–1.9s；
- P75 中心约 3.5–3.6s；
- 普通工作区间约 1.3–4.5s；
- 个别 punchline / 解释镜允许 5–8s 甚至更长；
- 近白背景占比中位约 81–83%，中心约 82%。

具体见 `references/VIDEO_CALIBRATION_PROFILE.md`。

# 2. 默认身份

- 主讲人：男性原创 IP；
- 叙述视角：第一人称；
- 人设：普通成年人、观察力强、会自嘲、有小心思、偶尔嘴贫、会把小事联想到荒诞大场面；
- 不是导师，不端着，不从答案终点说话。

正式个人IP模式：开场使用 `大家好，我是{{IP_NAME}}。`
校准演示模式：只有用户明确要求参考创作者口吻时，才可保留参考名作演示占位；正式发布必须替换成自己的IP名。

# 3. 四种核心内容模式

## M1 家庭/个人故事 → 人生观察
长辈、家人、成长经历、回家、旅行、一次具体经历。

## M2 社会现象 → 自己中枪 → 荒诞升级 → 观点
催婚、职场、买房、考试、社交、消费、稳定、代际差异。

## M3 当下状态/热点观察 → 连续吐槽 → 轻结论
城市现状、办公室共同经历、阶段性社会情绪。

## M4 自我观察 → 误判 → 连续生活证据 → 认知修正
精力、拖延、焦虑、效率、自律、社交电量等。

默认优先 M1/M2/M4；不强迫所有题目做“成长疗愈”。

# 4. 签名层（V3.2新增，默认开启）

加载 `references/SIGNATURE_LAYER.md`。

## 开头硬规则
第一句默认：

> 大家好，我是{{IP_NAME}}。

第二句必须立刻进入本期具体话题，常用：
- 我最近发现……
- 我最近特别羡慕……
- 前两天发生了一件事……
- 最近后台有人问……
- 今天讲一下……这件事。

禁止在签名后再铺 15 秒空背景。

## 结尾硬规则
默认：

中文落锤 → 0.5–1.0s语义停顿 → 一句 2–7 个英文单词的主题尾签。

英文尾签每条重新生成，不复制参考样本固定句子。

时效性强、节日/祝福型内容可用中文祝福替代英文，但这是例外。

# 5. 文案硬规则 V3.4

加载 `references/SCRIPT_ENGINE.md`、`references/CONTENT_DNA.md` 与 `references/LANGUAGE_PATTERN_PROFILE.md`。

1. 签名后立刻进入一个**具体事实/处境/事件**，不要先抽象定义主题。
2. 前 60–75% 以“我遇到了什么 / 我看到了什么 / 我当时怎么想”为主；观点明显后置。
3. **禁止泛化起手**：慎用“很多普通人 / 现代人 / 当代年轻人 / 大多数人的问题是”。优先继续说“我”，需要扩大时再自然转成“我们 / 大家 / 我们这代人”。
4. 默认推进不是“观点→例子”，而是 `事实 → 我反应 → 结果 → 联想/吐槽 → 另一个事实 → 再判断`。
5. 连接词优先使用自然口语的“但 / 结果 / 另外 / 不过 / 其实 / 而且 / 比如”；降低“说白了 / 归根结底 / 真正的问题是”等短视频导师腔。
6. “边说边修正”不是配额：一般 0–1 次即可，只有语义真的需要时使用。禁止为了像而硬塞“不对/准确地说”。
7. 笑点优先形成 **1–3 个连续 riff（梗链）**，每个 riff 可持续 2–5 句；不要平均每20秒机械插一个独立段子。
8. 至少一个笑点来自**主题词本身的变形/回扣**，至少一个来自现实生活细节；允许一处较长的荒诞类比。
9. 允许长口语句：真实样本单句中文字符中位约30，P75约41，偶尔可到60–90字；不要强行切成金句短句。
10. 现实摩擦必须具体：通勤、工作消息、家庭催促、钱、睡眠、手机、社交等；不要写成抽象标签列表。
11. 结尾回到“我现在怎么看/怎么做”，再轻轻扩大到观众；不要突然升格成课程总结。
12. 英文尾签默认**简单直译、略带翻译腔**，不要润色成广告 slogan；保持可理解，但允许轻微 non-native awkwardness。

# 6. 语言与语速

加载 `references/VOICE_SRT.md`。

默认：
- 5.9 中文字/秒；
- 口语意群 7–13 字；
- 完整句 22–38 字；
- 长句可以 40–60 字，但内部必须有 4–6 个口语意群；
- punchline 4–16 字；
- 少长空白，高密连续。

禁止为了“治愈感”把语速整体降成 4.x 字/秒。

# 7. 幽默引擎

加载 `references/HUMOR_ENGINE.md`。

优先：
- 自我降格；
- 精确反差；
- 荒诞类比；
- 字面化；
- 一词多义/双关；
- 文化文本结构挪用；
- 递进三连；
- 冷静语气说离谱事实；
- 回扣。

笑点必须同时推进人物、事件或观点之一。


# 7A. V3.4 文案收敛规则

以下规则来自继续复核真实旁白后的修正：

1. **抽象选题优先找一个具体配角/具体事件承载。**
   - 例如“高精力”不要一上来谈“高精力人群”，优先先讲一个真的高精力朋友/同事。
   - 如果题目本身就是个人独处事件，可不强行加配角。

2. **核心观点后置。**
   - 150–240s 稿件默认前 50–60% 先讲事件、观察、吐槽和证据；
   - 不要在前 1/3 就把“答案”完整说完；
   - 允许观众先跟着 narrator 一起误判，再一起改观。

3. **一篇只保留 1–2 个主梗母题。**
   - 优先把同一个比喻连续推 3–5 步；
   - 避免会员、手机、水桶、工资、工伤、后盖等每段换一个新比喻；
   - 新梗若不能推进人物/事件/观点，删除。

4. **结尾去方法论化。**
   - 不写成“该睡觉就睡觉、该拒绝就拒绝、该……就……”清单；
   - 优先继续说“我最近做到的一点小变化”，允许自嘲；
   - 最后才给一句轻判断。

5. **AI 演讲腔黑名单。**
   除非真实语境强需求，降权或删除：
   - 很多普通人的问题是……
   - 现代人的通病是……
   - 真正的问题是……
   - 归根结底……
   - 第一步不是……而是……
   - 你需要做的是……
   - 只要做到以下几点……

6. **英文尾签允许轻微翻译腔。**
   - 应像中文祝福被直接翻成英文，不追求漂亮 slogan；
   - 例如 `Wish everyone's battery full.` 这种“能懂但略别扭”的程度可以接受；
   - 不故意制造严重语法错误。


# 8. SRT

默认同时交付 SRT。

无最终配音：按 5.9 字/秒生成 provisional SRT；
有最终配音：必须重新强制对齐真实音频，provisional 时间作废。

# 9. 视觉语义拍

加载 `references/SHOT_GRAMMAR.md`。

核心：

> 不是每句话换图，而是每次“脑内画面发生语义变化”才换 visual beat。

多样本默认：
- 中位约 2.7s；
- 快反应/笑点 0.8–1.8s；
- 普通叙事 2.0–3.4s；
- 完整小场景/比喻 2.8–4.5s；
- 落锤/解释可 4–8s。

# 10. Visual Density Curve（V3.2新增）

不要全片一个密度。

默认：
- 开头：中高密度，快速建立人物/处境；
- 主故事：中密度，事件优先；
- 连续笑点/双关：局部高密度；
- 认知提炼：中低密度；
- 最后 10–18 秒：低密度，留给收束和英文尾签。

# 11. Punctuation Frames（V3.2新增）

白底漫画为主，但允许少量“标点型镜头”：
- 黑底/深底文字卡；
- 单色强情绪镜；
- 超大人物特写；
- 超大关键词/笑点字卡；
- 结尾落锤镜。

工程默认：全片 3–10%，不是主叙事方式。

# 12. IP 与资产复用

加载 `references/VISUAL_IP_BIBLE.md` 与 `references/IMAGE_GENERATION_PROTOCOL.md`。

原则：
> 镜头多，不等于新图多；新图多，也不等于新世界多。

工程默认目标（非实测比例）：
- 约 65–75% visual beat 优先由既有男主姿势/表情/小场景资产变体实现；
- 约 15–25% 为新的关系/场景/比喻构图；
- 约 5–10% 为真正的重锤特殊镜头。

资产优先顺序：
角色 Master → 表情/动作 Pack → 常用小场景 → 道具 → 本期特殊比喻镜。

# 13. 输出协议

用户说“用景岁 Skill 做 X”时，默认输出：

A. 选题切口
B. 内容模式 + 核心误判/反差
C. 完整口播稿
D. SRT
E. 分镜表：镜号/时间/旁白/画面/为什么换镜/Scene/是否新生图
F. Character + Scene Bible
G. 生图 Prompt 表
H. 剪辑与声音计划
I. QA

若用户只要求其中一项，只输出对应部分。

# 14. 成片 Gate

必须同时满足：
- [ ] 第一行是IP签名，随后立刻进入具体话题；
- [ ] 抽象主题若适合，至少有一个具体人物/事件承载，而不是全程谈抽象人群；
- [ ] 核心观点默认不早于全文约 50% 处完整揭晓；
- [ ] 全文主梗母题不超过 2 个，且至少一个形成连续梗链；
- [ ] 结尾不是建议清单，而是回到 narrator 自己；
- [ ] 未出现“很多普通人的问题是 / 现代人的通病是”等概念化演讲腔；

- [ ] narrator 是当事人，不是导师；
- [ ] 前15秒有具体人/事/状态，不是抽象命题；
- [ ] 至少50%口播描述具体人/事/物；
- [ ] 前半段没有提前把核心道理讲完；
- [ ] 有 1–3 个可持续2–5句的梗链，且笑点来自具体事件而非空降；
- [ ] 至少 1 次现实摩擦点；
- [ ] 不强制改口；如有，0–1次且必须自然；
- [ ] SRT 预计整体 5.7–6.2 字/s；
- [ ] visual beat 以 2–4s 为主但不机械；
- [ ] 白/浅底是主力，但有少量标点型镜头；
- [ ] 不连续3镜“人物站着 + 文字解释”；
- [ ] 最后10–18秒降低视觉密度；
- [ ] 中文落锤后默认有一句简短、略带直译感的英文尾签；
- [ ] 正式发布使用用户自己的IP名与原创角色。

# 15. 校准模式

## AUDIO CALIBRATION
转写、速度、句长、意群、开头结构、幽默机制、故事/观点占比、结尾方式。

## VIDEO CALIBRATION
实测换图点、visual beat 分布、构图、白底比例、人物/物件/比喻镜、微动画、标点镜头、资产复用模式。

多视频共同规律优先于单视频特例。
