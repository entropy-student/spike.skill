# Independent Store Operations（独立站运营系统）

一个面向独立站 / DTC 的通用运营诊断、站内转化、信任、商品决策、结账、履约、留存、内容与经济性 Skill。

它不是 CRO 技巧合集，也不是“AI 一键告诉你为什么不赚钱”的扫描器。

它的核心目标是：

> **先定位运营阶段与证据等级，再决定应该修、测、研究还是实验。**

## 什么时候使用

适用于：

- 有流量但没订单；
- 商品页浏览高但加购低；
- 加购高但开始结账低；
- 开始结账但购买低；
- 移动端表现明显更差；
- 退货 / 退款高；
- 客单低；
- 复购低；
- 营收增长但利润下降；
- 想检查一个独立站有哪些真实可观察问题；
- 想建立独立站内容体系；
- 想设计诊断规则或扫描器；
- 想判断某个运营建议到底应该直接改还是先做实验。

## 核心模型

```text
S1 人群与入口
↓
S2 商品发现
↓
S3 商品决策
↓
S4 信任与风险
↓
S5 报价与购物篮
↓
S6 结账与支付
↓
S7 履约与购买后
↓
S8 留存与传播
```

同时横跨：

- 数据；
- 经济性；
- 内容；
- 技术体验；
- 搜索发现；
- 合规与完整性。

## 证据纪律

### 店铺证据

- `L0`：公开页面 / 技术事实；
- `L1`：研究支持的合理风险；
- `L2`：该店自己的行为数据；
- `L3`：因果实验。

### 外部研究强度

- `R-A`：系统综述、元分析、标准、大规模长期研究；
- `R-B`：大型 benchmark、多案例实践研究；
- `R-C`：局部实验或案例；
- `R-U`：证据不足。

最重要的规则：

> `R-A 一般机制` 不能冒充 `L3 本店因果`。

## 三类规则

### H1 — 基础卫生规则

明确技术 / 可用性 / 一致性缺陷，例如：
- 关键页面报错；
- 主购买动作失效；
- 表单缺少标签；
- 商品结构化数据与可见价格矛盾。

默认动作：`FIX`

### C1 — 条件规则

必须先匹配店型，例如：
- 大目录是否需要搜索 / 筛选；
- 服饰是否需要尺码支持；
- 跨境是否需要关税说明；
- 订阅是否把续费和取消条件讲清楚。

默认动作：`CHECK APPLICABILITY → FIX / MEASURE`

### E1 — 商业实验规则

不存在通用最优答案，例如：
- 定价；
- 折扣；
- 免邮门槛；
- 免费退货；
- CTA 文案；
- 套装；
- 弹窗；
- 交叉销售。

默认动作：`MEASURE / EXPERIMENT`

## 店型模型

基础店型：

- `SINGLE_OFFER`
- `NARROW_CATALOG`
- `BROAD_CATALOG`
- `HIGH_CONSIDERATION`
- `REPLENISHMENT`
- `DIGITAL_SERVICE`
- `SUBSCRIPTION`
- `MIXED`

再叠加：
- 实物 / 数字 / 服务；
- 高客单；
- 尺码敏感；
- 兼容敏感；
- 跨境；
- 移动端为主；
- 新品牌；
- 强监管；
- 混合交易。

## 信息距离

不只判断“有没有信息”，还判断用户做决定时离这个信息有多远：

```text
P0 当前决策区
P1 一次明显点击
P2 全站可发现
P3 深层帮助中心
P4 未发现
```

## 交易拓扑

```text
T1 一次性购买
T2 周期订阅
T3 实物 + 独立会员
T4 免费试用 → 付费
T5 首期优惠 → 标准价
T6 第三方平台管理
```

特别适合处理订阅、数字服务、硬件+会员等复杂交易。

## 与其他 Skill 的分工

- **选品**：`independent-store-product-opportunity`
- **获客 / 增长实验**：`acquisition-growth-radar`
- **内容表达**：`short-form-spoken-script`
- **支付工程**：`payment-integration-governance`
- **部署治理**：`vps-project-governance`

## 调用示例

```text
按 Independent Store Operations 分析这个独立站。
先判断店型和当前症状属于 S1–S8 哪一段；
把页面事实、研究支持风险、本店行为证据和因果证据分开；
不要直接列一堆最佳实践；
告诉我当前最大瓶颈、关键 UNKNOWN、下一条最高信息价值证据，以及应该 FIX / MEASURE / RESEARCH / EXPERIMENT 哪一种。
```
