# Research & Design Audit — Independent Store Operations v0.6.0

## 1. 研究目标

本 Skill 不是收集“独立站技巧”，而是建立一套可长期复用的运营诊断理论：

1. 消费者从进入网站到购买、复购，需要跨过哪些决策障碍？
2. 哪些问题可以从公开页面观察，哪些必须依赖私有数据？
3. 如何避免把行业研究或相关性误当成单店因果？
4. 内容、获客、页面、结账、履约、留存怎样形成同一运营系统？
5. 如何把理论转成未来可测试的诊断规则？

## 2. 研究方法

优先来源：
- 官方标准与产品文档；
- 系统综述 / 元分析；
- 大规模电商 UX 研究；
- 监管机构规则；
- 真实独立站反例与公开页面校准。

降低权重：
- 单一品牌成功案例；
- 厂商营销材料；
- 单次社区观点；
- 未给出边界条件的“最佳实践”。

## 3. 理论设计上的关键决策

### 3.1 不做单一总分

原因：不同店型适用规则不同；页面事实、研究风险和因果证据不是同一层；总分制造虚假精确；一个严重故障可能比 20 个微优化更重要。

允许：分系统健康状态、evidence level、confidence、issue priority、unresolved unknown。

### 3.2 不把“最佳实践”混成一层

强制区分：
- H1 基础卫生；
- C1 条件规则；
- E1 商业实验。

### 3.3 不把“有没有信息”当充分条件

引入 P0–P4 信息距离：当前购买区域可见、一步可发现、全站可发现、深层帮助中心、未发现。

### 3.4 订阅不能只看“有无取消按钮”

引入交易拓扑 T1–T6，覆盖一次性、周期订阅、实物+会员、试用转付费、首期优惠转标准价、第三方平台管理。

### 3.5 信任不是徽章清单

信任拆为身份、商品、交易、履约、数据。评论只是 Proof 的一种，不是唯一形式。

### 3.6 扫描器不是因果引擎

公开扫描稳定覆盖 L0 和部分 L1；真实业务根因通常还需要 L2 店铺行为数据与 L3 实验。

## 4. 真实站点校准后的主要修正

真实站点样本暴露出以下反例：

- 高客单品牌通过试用、质保、配送、融资等不同方式降低风险，不存在唯一 Proof 组件；
- 大目录站和单商品站对搜索 / 筛选需求不同；
- 退货政策“收费”不自动等于体验差，清晰度和公平性比一刀切“免费”更适合通用规则；
- 一次性购买和订阅可能在同一商品页并存；
- 实物退货可能不会自动取消相关会员；
- “Cancel anytime”仍可能存在重要取消截止时间；
- 扫描遭遇限流、WAF、地区跳转时，必须判为审计不完整，而不是站点缺陷。

## 5. v0.6.0 验证状态

理论框架已经从“冻结待校准”进入“冻结且具备可执行验证基线”。

已完成：
- 77 条完整知识规则；
- 17 条首版可信规则；
- 51 / 51 正例、反例、边界 Fixture；
- 静态 / 动态事实提取验证；
- 多报价 / 订阅交易事实建模；
- 真实普通目标 9 / 9 可审计；
- 真实事实断言 26 / 26；
- 真实规则断言 28 / 28；
- unexpected ISSUE = 0；
- geo context misuse = 0；
- Scanner 网络安全与 connection-time pinning 验证。

这证明：

> **理论、规则与当前验证接口足够稳定，可以支持受限 Scanner 和后续产品化。**

这仍然不证明所有网站技术栈覆盖率相同、所有真实 ISSUE 已达到生产 Precision、页面风险等于营收根因、任意商业建议都可自动 FIX，或用户愿意为当前产品付费。

## 6. 后续研究重点

后续不再以“继续增加理论模块”为主，而围绕证据增量：
- 更多真实 ISSUE 人工盲审；
- false positive / false negative；
- 自动扫描 vs 人工审计；
- 授权店铺行为数据；
- 不同店型覆盖率；
- 规则适用性漂移；
- 部分商业建议受控实验；
- 内容、信任、报价与真实购买行为闭环验证。

## 7. 当前产品化状态

中断后 Recovery Review 已重新找到并验证完整产品源码快照：
- Scanner V0：当前 `55 / 55` tests PASS；
- WordPress G1 baseline：当前 `20 / 20` asset checks PASS；
- WordPress runtime GitHub Actions：PASS。

因此源码 UNKNOWN 已解除，下一产品 Gate 为：

`G4_WORDPRESS_SCANNER_TOP3_LOCAL_INTEGRATION`

这不重新打开理论框架；G4 仍只做本地产品闭环，不提前进入支付或生产部署。

## 8. 最终设计原则

> **先看事实，再定位阶段；先区分风险与根因，再决定修、测、研究还是实验。**

> **追求决策密度，不追求报告长度。**
