# Calibration Plan

## 目标

先跑 3–7 轮，不急着把分数公式定死。

要验证的是：

1. Run A 是否符合「我打开三个 App 后觉得今天最热的歌」。
2. Run B 是否能提前发现第二天/第三天继续上涨的歌。
3. Run C 是否比单一平台热歌榜更有价值。
4. S+/S/A/B 是否符合人工直觉：B=有热度，A=明显爆发，S=破圈，S+=现象级模板。
5. B 站维度是否能提前识别“音乐榜尚未冲高、但二创生态已经启动”的歌曲，同时避免被旧视频累计播放误导。

## 每轮人工反馈

对 Top 10 每首歌打：

- 2 = 很准
- 1 = 基本合理
- 0 = 不确定
- -1 = 感觉偏高
- -2 = 明显不准

并记录原因：

- 平台数据滞后
- 同歌不同版本错误合并
- 汽水推荐不等于热榜
- 跨平台重复奖励过高/过低
- 老歌长期霸榜挤压新趋势
- 飙升榜权重过高
- Social Breakout 权重过高/过低
- S/S+ 门槛过松导致等级通胀
- 音乐榜靠后但短视频爆发的歌曲被低估
- B站单个老视频播放过高导致误判
- B站同一UP主系列被错误当成多创作者扩散
- B站新投稿信号过弱/过强

## 第一阶段不优化什么

- 不做复杂机器学习
- 不预测播放量
- 不推断收入/商业价值
- 不抓音频
- 不做 BPM/Key 自动分析

先把「榜单事实」和「趋势评分」校准准。

## B站专项人工校准

每轮对候选歌额外检查：

- 最近 7 天是否仍有新投稿；
- 是否至少 2 个独立 UP 主；
- 是否存在 2 种以上二创形态；
- 高播放是近期爆发还是历史累积；
- B站信号是否领先音乐榜 1–3 天。

前 3–7 轮不根据一次结果固定 Bili 权重。
