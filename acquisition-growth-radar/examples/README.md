# Examples｜不同业务如何套用

以下示例只演示“证据层级和下一步”，不是固定答案。

---

## 1. 实物商品

### 情况
有一个新商品，用户反馈某个问题很烦，但还没有真实样品和成交。

### 判断
- Problem Evidence：可能 PASS
- Solution Proof：UNKNOWN
- Message Evidence：UNKNOWN
- Commercial Evidence：UNKNOWN

### 下一步
先做真实样品 Proof，确认哪些 Claim 成立；不要直接把用户抱怨写成广告卖点并开始大投放。

---

## 2. SaaS / AI 工具

### 情况
落地页有很多访问，注册率低。

### 不要直接判断
“流量质量不行”或“应该换广告渠道”。

### 先检查
1. Audience 是否正确
2. 用户看懂 Problem / Outcome 吗
3. Demo / Proof 是否可信
4. 注册价值是否足够明确
5. 注册摩擦是否太高

### 最小实验
保持渠道不变，只测试一个更具体的 Outcome + Demo + CTA，观察 qualified signup 是否改善。

---

## 3. 咨询 / 服务

### 情况
很多人私信询问，但几乎没人付款。

### 判断
Interest Evidence 很强，但 Transaction Evidence 弱。

### 重点排查
- 咨询者是否是真正决策人
- 是否有清晰交付结果
- 报价是否有参照
- 是否缺案例 / Proof
- 是否需要更低风险入口，如诊断、付费试点、短周期项目

不要因为“很多人来问”就写“需求已验证”。

---

## 4. 内容产品 / 课程

### 情况
一条内容爆了，粉丝增长明显。

### 判断
Attention / Interest Evidence 可能很强，但不能自动证明课程购买意愿。

### 下一步
设计一个和爆款主题高度一致的低摩擦商业动作，例如：

- Waitlist
- Workshop
- Paid mini-product
- Deposit / Pre-order

用真实交换验证 Commercial Evidence。

---

## 5. B2B

### 情况
目标客户数量少，无法靠大规模 A/B Test。

### 调整
证据单位从“海量点击”改为：

- Target account response
- Qualified discovery call
- Problem confirmation
- Pilot acceptance
- Paid pilot
- Contract value
- Sales cycle

B2B 的样本少不代表可以降低证据标准，而是应该使用更高质量的行为证据。

---

## 6. 继续上一轮

如果当前状态是：

```text
Problem Evidence: PASS
Solution Proof: PASS
Message Evidence: PARTIAL
Conversion Evidence: UNKNOWN
```

用户说“继续”时，应该从 Message / Conversion 开始，而不是重新搜索“市场有没有需求”。
